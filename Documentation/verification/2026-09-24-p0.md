## P0-A correction 1

Imports require the session snapshot already retained by `ArchiveImportPlan.build` / `resolving`; missing snapshots fail before publication, with no fallback open. The counter regression covers all seven editable formats, both ordinary imports and conflict replacements: **exactly two Finder opens**, the pre-publication verification and post-publication reload. GyoshukuKit's existing internal opens are outside this counter. Additions still compare only name/kind, including growing files; tar additions also model the writer's repeated-inode hard links (using staged identities for deferred additions).

The common projection now takes the actual output mode and the complete original entries, including removed hard-link targets. Split producers report whether they used the updater or rewriter, including ZIP fallback and format conversion. Audited against `ArchiveRewriter.validateRepresentability` / `carry`, the writers, and KaitoKit's entry readers:

| Carried entry | Expected output |
| --- | --- |
| Tar hard link | A surviving direct target (including a renamed target) preserves `.hardlink`, size 0. Removing the direct target materializes a separate `.file` for every surviving direct link, sized from the original chain's ultimate data target. Removing an intermediate link follows the same rule. Non-tar outputs materialize all hard links. |
| Directory | Rewrites emit size 0. ZIP updater preserves its stored size. LHA directory payloads are rejected by KaitoKit before editing, so writable LHA directories already have size 0. |
| Symlink | Tar emits size 0. ZIP/7z use UTF-8 target bytes when `linkPath` exists, or preserve the stored target-data length otherwise. LHA output refuses symlinks in the probe. |
| 7z empty stream / anti item | Reader resolves directory vs empty file before planning. Kinds and size 0 survive rewriting; anti metadata becomes false (an ordinary empty entry), matching the existing rewriter. |
| Sparse tar file | Reader exposes logical size; rewriter expands holes and retains that size and `.file` kind. |
| Root `./` / AppleDouble | Only rewrites omit an unrenamed nameless directory root. `.expose` keeps sidecars as ordinary entries; resource-fork pseudo entries are never used on these app paths. |
| ZIP password-only rewrite | Uses rewrite normalization, including empty directory payloads and root omission; stored symlink data lengths survive. Normal updater edits preserve these sizes and the root. |
| Unknown size / unsupported kinds | Normal editable readers provide sizes. ZIP recovery-only unknown extents are unavailable with the app's recovery-disabled reader options. `.other`, unsupported source methods/coders and unsupported output representations are refused before rewriting. |

Both reader-available `ArchiveCapabilities` probes now call `probe(reader:format:)`; projected/pending lists retain entries-only probes. Tests show MacBinary MacLHA envelopes and `-pm2-` members are read-only, assert the existing `RewriterError.unrepresentable` mapping, and check the reason is visible in `ArchiveWindowController.capabilityNotice`. Plain MacLHA remains editable. No new user-visible strings or localizations were introduced.
