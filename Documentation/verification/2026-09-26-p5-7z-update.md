## 実装

単一 7z の capability は `.update(.sevenZip)`、評価は `sevenZipAssessment`。
reader option は製品では `ArchiveReaderOptions.swift` だけで SPI を import し、通常 open と検証 open で記録する。
分割は従来の `.rewrite(.sevenZip)`。追加位置「先頭」も rewriter を使う。
既存の `writerOptions(for:)` の `additionPlacement` と P9 の `compressionThreads` はそのまま。
新しい defaults key と toolbar / menu 項目は無い。

publish は open だけで `requiresRewrite` を捕まえ、同じ publish で mutate より前に切り替える。
`willOpenUpdater` は一度だけ。updater 自己照合の失敗を既存の `updaterVerification` 診断で報告し、fallback しない。
7z の commit meter は publish 内だけで 1,000 単位を加え、呼出側の meter / sessionReader は使わない。
7z の rewriter fallback は削除済み entry と root を carry の予算から除き、完了時の total と completed を一致させる。

公開前の検証は並び順・種類・サイズを保ち、暗号化操作では `emptyStream == false` の entry の暗号化状態と、
stream の無い entry の非暗号化を別に照合する。fallback の projection へも暗号化の期待を渡す。
replay は「削除 → 改名 → `ArchiveReencrypting` の予約 → 追加 → フォルダ」。ZIP の予約順は固定乱数で旧順の出力と比較する。

7z updater の属性復元は mode と作成日だけ。APFS clone は元の xattr を保ち、sequential 出力は原本の xattr をコピーしない
（P5-A §A6）。既存の `preserveAttributes` は全 xattr をコピーしていたため、7z updater の呼出しだけでそのコピーを止める
引数を追加した。他形式・rewriter の属性復元と `additionalQuarantine` の規則は変更していない。

承認済みの solid-block notice を1キー、26言語に追加。既存キーはJSON値も含め変更無し。
S33 の probe trace 規則（保存は `representabilityDifferential` 必須、`planKeys` 禁止、全件の表現可能性検査は rewrite 時だけ）を保つ。
`KAITOFINDER_PROBE_ENCRYPTION=7z`、plain / encrypted header の fixture、direct updater、`PROBE-7Z` の戦略・byte・段時間を追加。
既存の `PROBE-TSV` 列の意味は変更していない。fixture cache version は4。

## release notes に書く変更

7zの改名・追加・削除は、変更のない圧縮データを保って更新するようになりました。ソリッドブロックの一部を削除すると、
そのブロックを再圧縮します。対応する7zでは、パスワードの設定・変更・解除も本文を再圧縮せずに行います。

既存項目の格納順と変更していない名前の表現を保ち、追加項目は末尾に入ります。設定で追加位置を先頭にすると、従来の全体の書き直しを使います。
一部だけ暗号化された7zは既存項目の暗号化状態を保ち、追加項目は現在のパスワードで暗号化します。
7z の anti 項目は編集の後も anti 項目のまま残ります（以前は空のファイルになっていました）
元の全項目が属性を持たない非空の7zでは、7zzと同様に追加項目にも属性を付けません（更新で追加したUnix modeは保存されません）。
7z updaterのAPFS以外の出力では原本のFinderタグ等のxattrをコピーせず、modeと作成日を復元します。分割7zの経路は従来どおりです。
