# 同名項目の比較・置き換え・複数追加

検証環境: macOS 27.0 (26A428)、Xcode 27.0 (27A266a)、arm64。
macOS 26 はビルド対象。この環境での GUI 検証は macOS 27 のみ。

## 操作

- ドロップ、貼り付け、「追加」、同じ書庫内の移動で、同名項目の比較シートを表示する。
- 「既存の項目」「新しい項目」を左右に並べ、種類、非圧縮サイズ、変更日、場所を表示する。
  フォルダは子孫の合計サイズと項目数を表示し、仮想フォルダも数える。不明な属性は `—`。
- 「内容を比較…」は二つの Quick Look ビューを別の比較ウインドウに表示する。
  通常ファイルが対象。フォルダ、リンク、複数の同名 record は属性の比較のみ。
- 置き換え、スキップ、キャンセルを選べる。Return はスキップ、Escape は全操作のキャンセル。
- 複数ファイルは一件ずつ判断でき、「残りのファイルにも適用」で残りの通常ファイルに同じ判断を使える。
  フォルダ、ファイルとフォルダの型違い、同名 record が複数ある場合は一括指定を使わず、別に確認する。
  フォルダは中身ごと置き換えることをシートに明示する。
- 同じ追加操作の入力同士が衝突する場合も確認する。最後に採用した一つだけを追加する。
  書庫間の file promise は元のパスを表示し、受信用の一時パスは比較欄に出さない。
- 全回答の後に一回だけ更新し、置き換えと衝突しなかった追加をまとめて一回の undo / redo で戻す。
  全件スキップ、キャンセル、受信・圧縮失敗では原本と undo 履歴を変更しない。

## 検出した問題と対策

以前は同名の項目が一件でもあると追加・移動全体を拒否していた。
新しい resolver は、原本を変えずに入力と置き換え対象を決定する。
確認待ちの後に原本の identity と世代を再照合し、入力ファイルも inode / size / mode /
mtime / ctime を圧縮前後・公開前に検証する。回答の途中で元データを変更する検査では、公開を拒否した。
置き換える record は updater 自身の一覧と照合してから削除し、照合情報のない plan も拒否する。

実ドラッグでは、別フォルダにある同名の `same.txt` を選ぶと AppKit が二つ目を `same 2.txt` に変更し、
比較画面に進まず二つとも追加してしまうことを再現した。
NSFilePromiseReceiver の契約に従って全 receiver に共通の保存先を渡し、すべての受信が完了してから
個別の領域へ元の名前で移す。ドラッグ開始時のパスと入力順を保持し、双方の内容を比較して選べるようにした。
受信処理は `@Sendable` callback と `@concurrent` の完了処理を使う。

比較欄の描画検査では NSTextField の整列矩形外の 2 pt が親領域からはみ出していたため、
スタックとグリッドにその余白を確保した。列幅を揃え、全言語での検査を通した。
既存の一般設定にあったフランス語のコロン前の空白も、他の翻訳と同じ改行しない空白に揃えた。
