# ドラッグ中のタブ切り替え

検証環境: macOS 27.0 (26A428)、Xcode 27.0 (27A266a)、arm64。
macOS 26 はビルド対象。実 AppKit の操作検証は macOS 27 で実施した。

## 動作

- ファイルをドラッグしたまま別のタブ上で約0.6秒待つと、そのタブを選ぶ。
- 書庫からの file promise と、Finder と同じ file URL の双方に対応する。
- タイトルだけでなくタブ全体で受ける。同名のタブも、それぞれのウインドウと対応付ける。
- 選択だけでは書庫を変更しない。切り替え後の一覧へドロップすると既存の追加・比較・置き換え処理へ進む。
- 短く通過した場合、離れた場合、ドラッグ終了・取消し、タブを閉じた場合は待機を解除する。
- 既に選択中のタブ、処理中・ロック中・シートを表示している書庫では発火しない。

## 実装と回帰防止

従来の `ArchiveDropIntegrationTests` はドラッグ途中に `makeKeyAndOrderFront` で切り替えていたため、
タブ上の静止による切り替えを検査していなかった。標準タブの表示位置へドラッグし、選択が変わるまで
待つ操作に変更するとタイムアウトすることを再現した。

`ArchiveTabSpringLoading` は公開の [NSWindowTab.accessoryView](https://developer.apple.com/documentation/appkit/nswindowtab/accessoryview)
から accessibility role を使って標準タブへ到達し、透明なドラッグ専用ビューを追加する。
標準タブの名前・描画・クリック先は変更しない。固定座標や非公開のクラス名・selector は使わない。
生成時にはタブ幅が0の場合もあるため、ドラッグ領域はタブの四辺に制約で追従させる。

静止中も動く common run-loop mode のタイマーを使い、発火時に最新の drag 情報と受け入れ条件を再照合する。
ビューの取り外しも待機を取り消す。Force Touch の入口は
[NSSpringLoadingDestination](https://developer.apple.com/documentation/appkit/nsspringloadingdestination) に接続する。
Force Touch の実ハードウェア操作は今回の自動検証の対象外。

テストは実際の `NSDraggingSession` を開始し、アプリ内にマウスイベントを送る。
ドラッグ開始直後の一度だけの大きな座標移動は AppKit の開始処理に吸収される場合があるため、
カーソルをタブまで段階的に動かし、到達後は追加の移動イベントを送らずに切り替えを待つ。
グローバル入力監視、他アプリへのイベント送信、画面収録・アクセシビリティの権限は使わない。
これはテスト本体についての記述。今回の前面化の診断では、既存の許可を使った外部の補助処理も試したが、
OS の `CGSSessionScreenIsLocked = 1` と loginwindow の表示を確認したため停止した。
新しい権限を要求・変更していない。
