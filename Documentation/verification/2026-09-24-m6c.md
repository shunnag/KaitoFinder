# M6c format-aware name rules

2026-09-24, macOS 27.2 arm64, `feature/2026-09-24-review`, base `69cc222`. GyoshukuKit: `95fef0e`; KaitoKit: `b518014`. Neither sibling was edited. No commit was made; the pre-existing review-plan / review-record edits were left alone.

Name validation now follows the edit's output format through import, rename/move, new folder, rename-field validation, deferred reservation/replay, and edit indexes. Only tar / tar.gz / tar.bz2 / tar.xz permit `:` and `\`; context-free calls retain the ZIP default. Other checks and messages are unchanged. Conversion still probes the selected output format and reports the existing unrepresentable error. Extraction and the 26-language string catalog are unchanged.

`M6cNameRuleTests` covers:

- Plain tar and tar.gz in immediate and onSave modes: capability, deletion, folder/leaf renaming, moves, new folders, disk imports, duplicate refusal and conflict resolution. Saved names are compared as raw UTF-8 bytes, and payloads are checked.
- ZIP's existing rename/import messages; all seven output formats' name rules, strict defaults, NFC, invalid components/NUL, and the 65,535-byte boundary.
- Cached occupancy after deferred edits, additions and folder creation. Diagnostics assert zero full validations, base-validation rebuilds or replay plans during reservations. An unsafe-base control confirms the full-validation counter fires on fallback.
- Tar Save As with pending edits; tar/tar.gz conversion to ZIP, 7z and LHA, with and without pending edits and split output, retaining the unrepresentable message and original bytes.
- POSIX colon bytes on extraction and `ExtractionDestination`'s refusal of backslashes inside output components.
