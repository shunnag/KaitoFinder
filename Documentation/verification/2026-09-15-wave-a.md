### 2. Swift のモジュール生成・型検査 — 通過

Python の `subprocess.run` から、ソース一覧を引数として `xcrun swiftc` を呼んだ。
以下は同じ引数のシェル表記。出力とモジュールキャッシュは `/private/tmp` に限定し、
既存の KaitoKit / GyoshukuKit モジュールと C ヘッダーは読み取りだけに使用した。

```sh

xcrun swiftc -emit-module -parse-as-library -enable-testing \
  -emit-module-path "$checkdir/KaitoFinder.swiftmodule" -module-name KaitoFinder \
  -swift-version 6 -strict-concurrency=complete -default-isolation MainActor \
  -enable-upcoming-feature NonisolatedNonsendingByDefault \
  -enable-upcoming-feature InferIsolatedConformances -target arm64-apple-macos26.0 \
  -I "$products" -I ../KaitoKit/Sources/CBzip2 -module-cache-path "$checkdir/ModuleCache" \
  $(rg --files KaitoFinder -g '*.swift')

xcrun swiftc -typecheck -module-name KaitoFinderTests \
  -swift-version 6 -strict-concurrency=complete -default-isolation MainActor \
  -enable-upcoming-feature NonisolatedNonsendingByDefault \
  -enable-upcoming-feature InferIsolatedConformances -target arm64-apple-macos26.0 \
  -I "$checkdir" -I "$products" -I ../KaitoKit/Sources/CBzip2 \
  -I "$sdk_developer/usr/lib" -F "$sdk_developer/Library/Frameworks" \
  -module-cache-path "$checkdir/ModuleCache" \
```

## 追補: ユーザー側検証後の 3 点修正

### 入力された検証結果と修正

ユーザー側のシェルで **build 成功、544 テスト・16 失敗**。これは修正前の結果であり、
今回の sandbox で測定した結果ではない。指摘された 3 点に限定して修正した。

1. **隠し項目の追加テスト**: `._file` と `Docs/._file` の fixture は保持し、期待集合から
   AppleDouble を除外した。macOS の Foundation がこれを列挙しないことをコメントと
   `design.md` §7.8 の 1 文に記載。4 通りの設定組み合わせの検査は維持し、製品の追加処理は変更していない。
2. **カスケードテスト**: 製品の参照ウインドウ検索を internal static の
   `ArchiveWindowController.cascadeReferenceWindow(excluding:)` に抽出し、`showWindow` と
   テストで共有した。テストは開始時と各 `showWindow` の直前に、自分が作ったもの以外の
   アーカイブウインドウを `close()` する。期待する座標は直前に得た実際の参照から求め、
   参照なしの場合は nil と frame 不変を検査する。表示済みウインドウの位置が変わらない検査も維持した。
3. **保存アクセサリのはみ出し**: 幅を 360 pt に固定。暗号化不可・固定レベルの両注記を
   左揃え・副次色の wrapping label に統一し、左右各 2 pt の inset を引いた 356 pt を
   `preferredMaxLayoutWidth` と幅制約に指定した。高さは折り返しに合わせて決まる。
   10 言語 × 5 形式の既存描画検査は維持し、幅が常に 360 pt であることも検査する。
