Applied to M2 commit `f4565d0` on `feature/split-archive-editing`, without committing, switching branches, launching companion tooling, or modifying KaitoKit/GyoshukuKit. The original specification, both earlier corrections, implemented API/table, M2 sources/tests, and round-3 specification/review were read. Existing M3/M4 changes were preserved; the only edits to the already-modified AppDelegate are its launch/didMount volume-recovery calls. The table below describes the current implementation; round-2 coverage and execution results remain as history.

## API

`VolumeSetPublication.begin(_:estimatedOutputLength:progress:index:options:coordinationTimeout:criticalSection:operations:fault:)` returns an owned staging/work URL. The caller writes `workURL`, verifies assembled input, then calls `publish(progress:validation:)`. S4 still validates with the caller's `ReaderOptions`. S0 passes those options and the caller's file presenter to recovery. Recovery never needs credentials or a reader to accept S4-validated, hash-proven volumes. The optional `recoveryReaderDiagnostic` observer requests a reader check only after durable commit, using caller options; reader errors are reported to that observer and cannot block commit.

`VolumePublishRecovery.recover(staging:options:presenter:)` supports document-initiated recovery. The overload with `alreadyLockedGate` receives the volume metadata/root captured before `begin` took that lock. Recovery discovery runs before the recovery mutex; `recoverLocked` accepts the computed metadata, index entry and mount evidence. `recoverAll(parents:mountedVolume:)` serves launch and didMount through `VolumePublishRecoveryQueue`, a dedicated serial utility DispatchQueue that coalesces concurrent requests for the same index/mount. Its async launch bridge suspends the caller without blocking a cooperative-pool thread. Results remain `recovered`, `held`, and `owned`.

`PublishedVolumeSet` still returns layout, identity, disposal, rename-fallback flag and `.committed(cleanupFailed:)`. In-process reader/environment failures keep the placed set and backup (`publishedReaderFailed`/`publishedVerificationPending`); subsequent recovery accepts the full byte proof. `rolledBack` separates the original failure from cleanup failure. `rollbackIncomplete` is reserved for an actual failed restoration.

`VolumePublishOperations` retains real reader/Trash/filesystem defaults. Removal is no longer replaceable with a path-based implementation: `willRemove` and `didRemove` observe/fault individual fd-relative operations. Local and non-local mount enumeration and the descriptor-relative staging rename are injectable. Journal flock and process-identity probes can be injected for deterministic fallback tests. There is no production coordination bypass.

## Durable removal and ownership

Staging remains `.KaitoFinder-vol-<UUID>/{work,new,old,journal}`. A per-staging flock in local Application Support `staging-locks/` is acquired **before** index registration, and retained through publication/recovery/disposal. The index records its name and whether the target was non-local, and is durable before mkdir. Recovery acquires the same lock by staging UUID even when there is no journal or the index uses a different path spelling. The journal is closed after its last write and identity check, before renaming staging. The independent staging lock keeps ownership during that gap.

`VolumePublishRemoval.discard` normally checks the held staging identity and atomically renames it through the held parent fd to `.KaitoFinder-vol-<UUID>.discard`, then flushes the parent. That name is durable authorization to finish deletion even if both journal slots, the journal file, or the index are missing. On a non-local target only, `EBUSY`/`EACCES` from this rename permits the already-proven discard in place. It uses the same held descriptors and keeps the journal last: an interrupted prepared discard is reclassified from its remaining journal/content; after journal deletion all reserved regions have already been removed. Local rename failures and other errors still HOLD.

The only recursive removal primitive is descriptor-relative: `openat(O_DIRECTORY | O_NOFOLLOW)`, `fstatat(AT_SYMLINK_NOFOLLOW)`, and `unlinkat`. Each recursion uses retained directory descriptors; symlinks are unlinked themselves, never traversed. Directory identity is rechecked before removing its name. It deletes the journal last. Interruption leaves either a discoverable tombstone or the indexed staging for the network fallback. Reserved old/ removal after failed Trash uses the same primitive. Cleanup of a recreated/changed name fails closed.

Old data is removed only after its remaining journal-named contents are proved and a fresh final new-set **length + SHA-256** proof succeeds, with the next name absent both before and after hashing. The proof is repeated after a failed Trash attempt, immediately before permitting removal. When new data is missing/corrupt, recoverable Trash is permitted; failed Trash keeps old/ and returns HOLD. Durable `done` never authorizes restoring old data over later user edits.

Explicit AppleDouble sibling moves require the volume capability (`ATTR_VOL_CAPABILITIES`, `VOL_CAP_INT_EXTENDED_ATTR`), falling back to msdos/exfat/smbfs/afpfs/webdav when capability information is unavailable. Only the exact `._<journal volume name>` sibling is moved. APFS/HFS+ always leave independent `._*` siblings alone. With an unreadable journal, no `._*` name is attributable as a sidecar: any such entry in old/new/abandoned is evidence requiring HOLD, including a real volume whose stem starts with `._`. Only `.DS_Store` is ignored in those journal-less emptiness checks. A valid tombstone authorizes removal of its own contents, never traversal outside it. Native xattrs continue to use fd-based APIs.

Journal ownership remains nonblocking flock, with boot-session/PID/start-time fallback. A local registry tracks live journal ownership. A matching current-process PID is stale once the publication/recovery releases its journal; live local ownership and live foreign processes still block. Set locks use volume UUID + parent inode + gate normalized to NFC before case folding; gate inode is excluded.

Discovery reads the index first and tries the **stored path first**. An empty index performs no mount probes. An existing path needs only its own volume UUID and a journal naming that staging/gate (or a durable tombstone); unknown and duplicate UUIDs do not prevent content-based recovery there. No automatic rebase replaces a still-working stored path. Index lookup also matches `(volume UUID, relative staging path)`, so boot Data firmlink spellings find the same entry and completion updates the recorded path.

Only unresolved known UUIDs trigger one `getmntinfo(MNT_NOWAIT)` enumeration per pass. Its cached flags/types exclude non-local, autofs/devfs/nullfs/devicefs and FSKit mounts before opening them, unless an unresolved entry records a non-local volume. UUID probing uses actual `ATTR_VOL_UUID` values, with Foundation fallback. Each candidate has a one-second bounded wait on a separate thread; at most four probes may remain outstanding and subsequent passes reuse a stuck root's probe. A timeout/incomplete enumeration cannot authorize pruning. Mount discovery and metadata probes run outside the recovery mutex and set locks. didMount probes only the notified volume and never enumerates the others. I/O on an entry's own target can still wait on that filesystem; the serial recovery queue keeps it off the Swift cooperative pool.

Stored-path and didMount completion deliberately retain index hints because neither proves UUID uniqueness. They do not set the index's legacy cleanup authorization, which could otherwise misclassify a still-incomplete clone. A later pass may prune a missing hint only with a unique known UUID, safe relative path, matching recorded parent inode, and both staging and tombstone absent under the staging/set locks. Unique UUID resolution may remove a hint after completing recovery there. Unknown UUIDs, cloned/multiple matching mounts, missing parents, and insufficient legacy evidence retain their entries. Existing optional index/journal fields remain decodable.

## Recovery decision table (priority order)

| Evidence | Action |
|---|---|
| Staging lock currently owned, including pre-journal S1 | Return `owned` before probing mounts or touching the staging. |
| Valid `.discard` name | Finish fd-relative deletion and flush; journal is unnecessary. Automatic stored-path/didMount recovery retains the hint pending a unique-volume proof. |
| Absent staging/index hint | Require a unique known mounted UUID, safe relative path, matching parent inode, and absent staging **and tombstone** before pruning. Otherwise HOLD. |
| Set lock/journal currently owned | Return `owned`; never modify that publication. Own-process stale fallback metadata is not ownership. |
| Unreadable journal, reserved old/new/abandoned regions empty apart from `.DS_Store` | Discard incomplete preparation. Every `._*` name counts as unproved content and HOLDs. |
| `done` | Cleanup only. Re-prove the live new set before authorizing old-data unlink. Failed proof plus failed Trash keeps old/, records `keptOldVolumes`, and reports cleanup HOLD. A readable, valid done journal never blocks a subsequent begin, even after later saves replaced its new set. Never restore or move live names. |
| Completed cleanup authorization, journal-named reserved regions empty | Tombstone and finish cleanup. Interrupted tombstone cleanup no longer relies on this index marker. |
| Prepared with no retirement/placement evidence | Discard owned preparation, independent of later live-set changes. |
| Durable `abandoned`, old/ has no journal-named volumes, remaining abandoned volumes hash-proven | Dispose generated abandoned data and clean up. Later live edits, next-name occupants, and presenters are irrelevant. |
| All new volumes hash-proven at final names, old generation accounted for | Fresh full hash/length/next-name proof, durable done, then cleanup. No reader or live-name coordination is required. |
| Complete new set in staging/final positions and all old volumes accounted for, no forward conflicts | Coordinate, finish gate-first retirement and gate-last placement, prove final bytes, commit, dispose old, clean up. |
| Abandoned/incomplete new generation with a provable old generation | Coordinate; withdraw our new gate first and remaining new volumes, then restore old siblings and old gate last. Restore uses the held parent fd even if its path was renamed. |
| No old volumes remain to restore | Skip restoration occupancy/next-name checks. The live names may have changed independently. |
| Foreign occupant in new names or the new next name; content mismatch during final rehash | Withdraw proven new volumes and attempt old restoration. Preserve every foreign occupant. Failure to prove/restore old data HOLDs with the backup retained. |
| Foreign old-only name beyond the new next-name gap on a shrink | Ignore for forward classification and already-retired old volumes. Preserve it. It matters if backward restoration needs that name. |
| Neither direction is provable, unsafe path, unavailable resource, or unexpected failure | HOLD and retain evidence; never delete on uncertainty. |

A presenter on **any volume** of the set (path or file identity) blocks only an actual live-name move. Prepared discard, done cleanup, completed rollback disposal, and all-final forward completion do not HOLD for presenters. Recovery excludes the supplied document presenter and uses it in `NSFileCoordinator`; move claims cover old/new members, and presenter checks are repeated before rollback or retirement. If a cleanup-only proof discovers a new conflict, recovery must acquire coordination and check presenters before withdrawing anything.

Parent durability barriers still separate gate retirement, sibling placement, new-gate visibility, withdrawal and old-gate restoration. S6–S11 execute outside the caller's cancelled Task while holding the coordinator/access/activity lease. S5 now enters the critical section before its final cancellation check; cancellation releases that lease without entering S6. An atomic `closeIfIdle` prevents new leases after either immediate or deferred termination has been granted, including the deadline path.

S0 scans only stagings proven to name its stem by journal or index; unreadable unrelated/unattributed siblings are untouched. After attempting cleanup, it re-reads and validates the journal; a readable `done` staging cannot block a later save because of held old cleanup, regardless of which generation is now live. The `keptOldVolumes` field is diagnostic, never permission to unlink without the live-copy proof. Occupancy and expected identity are checked again after S0 recovery.
