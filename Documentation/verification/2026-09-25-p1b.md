# P1b / S8: ZIP の暗号化変更を updater へ移す

2026-09-25、KaitoFinder `feature/2026-09-24-review`、基底 `a113d94`。
依存は KaitoKit `24311ac`、GyoshukuKit `e62e3b7`（S7）。両 sibling の編集・コミットは行っていない。
計画の P1b 行には、既に KaitoKit / GyoshukuKit / KaitoFinder の三つが記載されている。

## 実装

- 単一 ZIP の設定・変更・解除と `outputEncryption` を含む保存を `.inPlace` へ移した。
  `ArchiveUpdater.open(url:output:options:)` が公開前の門番を引き受け、事前の重複 open は削除。
  replay は変更・追加・フォルダの予約後に `reencryptExistingEntries(currentPassword:)` を予約する。
  7z は従来の rewriter。他形式・別名保存・形式変換の replay は既定引数で従来のまま。
- `publish(..., commitProgress:)` と分割の commit にバイト進捗を渡す。
  `ArchiveReencryptionProgress` は単調な 1000 単位へ写し、callback ごとに取消しを確認する。
  replay の件数と公開の一単位は別に残す。
- ZIP 暗号化変更の commit が `nonRelocatableEntry` の場合だけ rewriter へ戻る。
  失敗した試行の進捗を戻し、projection も rewrite の出力規則に切り替える。
  分割の open 時の構造的拒否による既存の fallback は維持。
  暗号化変更のない分割 commit の失敗は fallback しない。
- `reencryptionFailed` は実際の失敗として返し、構造的拒否・パスワード再入力・恒久的編集拒否にはしない。
  `ArchiveSplitWorkProducer.isStructuralRefusal` は明示的に false。
  GyoshukuKit の `UpdaterError` / `RewriterError` / `WriterError` と関連 switch を `rg` で確認した。
  新 case で壊れる網羅 switch は `isStructuralRefusal` と `ArchiveErrorText` の二つ。
  後者に日本語・英語の試験と 26 言語の文言を追加した。新 key の括弧は ASCII。
- `ArchiveOutputProjection` に ZIP の目標暗号化を渡し、各 entry の `isEncrypted` と
  `formatSpecific["encryption"]` を両方照合する。通常ファイル以外は平文を要求する。
  単一出力・分割作業ファイル・分割公開時・rewrite fallback に同じ検査を適用する。
  不一致は専用の検証診断に記録し、単一公開では既存の `ArchivePublicationError.verificationFailed` を返す。
- 公開後の鍵の採用、verified reader の採用、undo の退避、P1c の編集前検証は維持。
  S1 の password probe は `updater_open` を要求し、`rewriter_open` を禁止する。

## 正式な受入計測の残件

100,000 / 500,000 entries と 256 MiB の最適化 Debug による変更前後の同条件比較、
ZIP の P0b 全行の ±10% 比較、通常 host の指定クラスと UI を含む全件はオーケストレータで実行する。
小規模の非最適化実行を A15 の速度合格には置き換えない。

S1 の当時の小規模基準は [手順 0 の記録](2026-09-25-p0b-stage-probes.md#s1-の実行結果2026-09-25)。
500k AES fixture の作成は依然として writer の直列 PBKDF2 を使い、仕様の見積りは約 152 秒
（今回の実測ではない）。P1c が既にあるため、編集前の検証の速度と commit の改善を分けて比較する。
`password_verification` と `total_without_password_verification` は残している。

APFS 以外では output mode の snapshot copy と暗号化変換で全体を約二回書く見込み。
従来 rewrite は一回であり、再圧縮省略だけで一律の速度向上を保証しない。今回その volume での実測はしていない。
