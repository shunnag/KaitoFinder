# 2026-11-22 KaitoFinder 0.10.12 (26) の起動と署名検証

## Finder からの起動

macOS 27.3 で GitHub の 0.10.11 を展開し、LaunchServices に ZIP とアプリの URL を渡して新しいプロセスを起動した。アクセシビリティ API でそのプロセスのウインドウを観察すると、「ようこそKaitoFinderへ」が一覧より前に残った。0.10.9 で追加されたテストは、AppDelegate の Swift メソッドを直接呼んでいた。登録済みの書庫は AppKit が文書コントローラに渡す。

0.10.12 は起動完了通知の `NSApplication.launchIsDefaultUserInfoKey` を確認し、書庫の表示要求を受けた時点で表示済みのようこそを閉じる。以下は表示設定オンでの実測。

| 操作 | 0.10.12 のウインドウ |
|---|---|
| 小さな ZIP を指定して起動 | ZIP の一覧が 1 枚 |
| ZIP を 2 個指定して起動（片方は 12,000 項目） | ZIP の一覧が 2 枚 |
| アプリだけを起動し、続いて書庫の open-documents イベントを送信 | 最初はようこそ 1 枚。受信後は ZIP の一覧が 1 枚 |

専用の設定ドメインに起動時表示オフを保存した検証コピーでは、アプリだけを起動してもウインドウは表示されなかった。
