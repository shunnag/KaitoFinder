## このリリースで配布する変更

- 独立した modern LZ4 block の文法と展開後サイズを並列に検証し、小 block をまとめる。4〜64 KiB block の 64 MiB で 0.10.9 の 2.2〜2.6 倍。
- LArc の `-lzs-` 画像は約 1.8 倍、`-lz5-` 画像は約 7% 短縮。
- ZIP PPMd（variant I）の文書は約 16%、7z PPMd（variant H）は約 8%、実 product.cab の LZX は約 6% 短縮。
- RAR 2.0 の biglz は約 1.7 倍、RAR 1.5 の文書・音声は約 15〜28% 短縮。
- lh5 は Mac mini M4 の text / binary で約 5〜19%、さらに長い一致のある入力で 5〜15% 改善。LZW は Mac mini M4 で約 0.4〜4.5%（M4 Max は ±1% 前後）。BZip2 は連続バイトの多い入力で約 3〜5% 短縮。出力は変更前と byte 一致。

## レビューで残った指摘

- **文書（修正済み）**: 既知の問題と `limitations.md` は、辞書上限の緩和を今後の課題としていた。8 GiB の選択肢は 0.10.8 から利用できるので、0.10.10 の文書を訂正した。公開済みの旧版のノートは変更していない。
- **KaitoKit 0.22.0（未修正）**: `LZ4FrameDecompressor.swift` の `parallelPlan` は全 lane を完了してから結果を調べるので、不正な block が先頭にある frame でも全 block を処理し、処理中はキャンセルが効かない。0.21.0 は最初の失敗で止まった。frame は最大 256 MiB の入力に制限され、失敗後は直列経路で同じ出力・error になる。不正な約 256 MiB の frame で数十 GiB 相当の復号が走り得ると静的に見積もったが、実測はしていない。低重要度の回帰で、KaitoKit の次の版で共有の失敗フラグとキャンセル確認を入れるのが候補。

## 既知の問題

- 開いているアーカイブを Finder などで名称変更・移動すると、そのウインドウでプレビュー・クイックルック・展開ができなくなることがある。以前の版からある問題で、今回の対象外。
- コーデック辞書の上限は既定で 1 GiB、物理メモリ 32 GiB 以上の Mac では 8 GiB を選べる。選択した上限を超える実確保が必要な RAR5 compression version 1 書庫は展開できない。
- custom RAR VM、RAR 1.3 / 1.4 の Data からの継続巻・ASCII 以外の password、CAB Quantum は引き続き未対応。
