## 選択変更の測定

`ScenarioScaleTests.testRepeatedSelectionsInAHundredThousandEntryTreeStayResponsive` は、100個の
フォルダに10万ファイルのメタデータを置き、50回実際に `NSOutlineView` の選択を変更する。
時間にはステータスバーとパスバーの同期更新を含め、木の構築・初回表示は含めない。
最後の選択件数・選択サイズ・表示文字列も確認する。

| Debug、同じMac | 50回の選択変更 |
|---|---:|
| 変更前 | 1.532786秒 |
| 変更後 | 0.001420秒 |

最終の全694テスト中の再実行では0.001341秒だった。

これは選択時の全件集計を除いた効果であり、アーカイブを開く時間や展開速度の改善値ではない。
実行時には関連フレームワークのテストも動いていたため、厳密な負荷統制をしたベンチマークではない。
最適化後のアルゴリズムは、件数のための O(全項目数) の再走査を選択変更経路から除いている。

## 編集計画・保存予約の測定

`ArchiveEditScaleTests` は合成したentry metadataで表示上のフォルダを選び、実際の編集計画を作る。
GyoshukuKitの `ArchiveEditingScaleTests` は実際の書庫を作り、追加→全件改名（中間でさらに追加）→
commitを通す。予約の時間はopen・初期追加・commitを除く。完成したZIP・tarは全ファイルの内容を
読み戻して比較し、旧パスの再利用も確認する。

| Debug、同じMac | 1,000件・変更前 → 後 | 2,000件・変更前 → 後 | 4,000件・変更前 → 後 |
|---|---:|---:|---:|
| アプリのフォルダ改名計画 | 0.7665 → 0.0224秒 | 3.2808 → 0.0451秒 | 13.0795 → 0.0892秒 |
| GyoshukuKit ZIPの改名予約 | 1.5467 → 0.0102秒 | 6.3320 → 0.0196秒 | 25.9501 → 0.0391秒 |
| GyoshukuKit tarの改名予約 | 1.6430 → 0.0100秒 | 6.7165 → 0.0205秒 | 27.3892 → 0.0423秒 |

5,000フォルダ・10,000項目の削除計画は15.9107 → 0.0490秒。
これらは計画・予約の測定であり、展開・再圧縮・全体の保存時間を含む値ではない。
同時に他の検証が走ることもあり、厳密な負荷統制をした測定ではないが、入力規模を2倍にしたときの
二乗の増加がなくなったことも確認した。GyoshukuKitの遅延プロパティに値型の索引を置くと辞書の
copy-on-writeが残るため、所有するeditor専用の参照型にしている。

索引の差分検査は、挿入・削除400手の各段階で、全件を比較する独立した判定と受理・拒否を照合する。
同名、NFC/NFD、ファイルと親子、空成分、結合文字の境界も含む。アプリは表示名、ZIP updaterは
元のレコード名という比較対象の違いを保ち、frameworkの公開APIは増やしていない。
当初はCharacter単位の従来判定と照合した後、上記の結合文字による見逃しを再現したため、
判定基準をNFC化したUTF-8の区切りへ修正した。索引は成分の木であり、全接頭辞の文字列を
保持しない。深さ16,000の索引単体テストで照合・解放・枝の再利用も検証する。
writerへの追加と改名を毎回交互に行う呼び出しでは、追加直前の全名同期が残る。
KaitoFinderの一括改名・移動はその呼び出し方をしない。

## 小さな整理と残る経路の確認

- 編集可否は実際に全編集操作が使っていた `canAppend` を `canEdit` に改名し、常にfalseを返す
  未使用の `canDelete` / `canRename` / `canEditAttributes` を除去した。UIとモデルの条件は同じ。
- パスワード検証は128 KiBの読み取りバッファをentryごとに確保せず、同じ検証内で再利用する。
  認証・CRC/HMACの検査や取消し確認は省かない。速度向上の数値は主張しない。
- 表示状態の復元、設定値の型・範囲チェック、保存パネルの形式・暗号化・取消しの流れを確認した。
  ここでは追加の確定した不具合は見つからなかった。

## 変更しなかった範囲と制限

- 読み込み時にsession、編集可否検査、updater / rewriterが別々に解析する箇所は残る。
  編集側の形式検査と原本の再照合には役割がある。検査を省略する変更や、reader共有の公開API追加は
  今回行っていない。必要なら起動時間を別途測り、再照合を保つ形で検討する。
- コピー取消し後の未公開一時ファイルは、現仕様と既存テストで次回起動まで保持される。
  このレビューでは寿命の契約を変更していない。公開済みclipboard URLの保持と合わせた
  独立のディスク使用量改善として扱える。
- 外部コーパス未設定のKaitoKitテストと、テストホストを前面化できないQuickLookテストは
  スキップを成功と数えていない。TSan / ASanは同日以前の記録があるが、今回の変更では再実行していない。
