## 実装

- `EntryNameMatcher` は、名前全体が印字可能 ASCII の場合だけ byte の照合または指定範囲の Lo による不一致を使う。
  その他は従来と同じ Foundation の options。`EntryNode` は保持前に名前を contiguous UTF-8 にする。
- filter は root を強参照し、設定とともに identity を検証する。取消し可能な構築は二つの走査の各1,024 nodeで確認し、
  `.userInitiated` の要求から `@concurrent` で計算する。空の検索語の構築は main-thread counter の対象外。
- requested と applied の検索語・隠しファイル設定を分けた。空の検索語は常に同期、通常は20,000 node未満も同期。
  token・木・設定・世代・locked を検査し、改名・操作・ドラッグ・Quick Look・シート・一覧メニューの間は差し替えを保留する。
  待機中は controller を強参照しない。旧 filter と使わない計算結果は背景で解放する。
- 差し替え時の選択・展開状態を復元し、古い子一覧で collapse した後に filter と query を置き換える。
  `display` は要求した設定を採用し、異なる木・設定の prepared filter は同期の fallback にする。
- 初回表示の二つの枝と即時編集・undo・外部変更後の表示でも filter を背景で用意する。
  初回表示で検索語が空なら準備を呼ばない。保存時モードの既存の準備経路はそのまま。
- 500 ms後に `検索しています…` を表示する。読み込み表示は別の状態で持ち、共有 indicator と accessibility label は読み込みを優先する。
  設定の注意書きの再計算は `preferencesDidChange` の先頭に残した。

新しい defaults key はないため `TestProcessSetup.autosaveKeys` と `AutosaveIsolationTests` の追加は不要。
新しい文言は指定の1キーだけで26言語すべて translated。既存の翻訳は変更していない。
既存の通常動作の試験の変更は、指定された `M6bSearchTests` の3か所の await のみ。
`WordingAcceptanceTests` の1件と `PerformanceProbeTests` の opt-in probe は仕様どおり追加した。
