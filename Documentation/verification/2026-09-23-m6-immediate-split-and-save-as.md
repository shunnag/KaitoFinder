# M6: immediate split editing and split Save As

Implementation on `feature/split-archive-editing`; no commit or branch switch. KaitoKit and GyoshukuKit were read for API verification and were not modified.

## Immediate edits

`ArchiveCapabilities` marks writable numbered uniform sets as `splitSave` and `splitIrreversible` for immediate documents. Uneven immediate sets have the specified Settings refusal. Native split ZIP retains its existing refusal. Direct single-file publishing still has the unchanged M0 guard.

Every document edit entry point uses the existing pending-plan builders with a temporary `ArchivePendingEditor` for an immediate split edit. Add/paste/drop and extracted in-archive copies use append; delete/rename/move/folder/password and conflict replacements use the same shared reservation boundary. The temporary plan is published immediately and its staging is released after completion. It never registers deferred undo or makes the document dirty.

After identity/capability checks and before planning, the injectable `splitMutationConfirmation` presents the specified irreversible-change message, explanation, Change/Cancel buttons with Cancel as default, and per-archive suppression checkbox. The deletion UI delegates split confirmation to this shared boundary. Existing password and conflict UI still receives `canUndoNextMutation == false`. Progress sheets yield to confirmation and hazard consent, then resume. Hazard consent uses M5's sheet and is keyed by destination directory, volume identity and hazard kind. A backing-file switch clears consent and confirmation suppression.

`publishSplitChanges` shares M5's schedule selection, hazard checks, presenter exclusion, outcome notices, reload and gate modification-date handling. Immediate edits retain the saved schedule (or inferred S when no schedule is saved) and refuse the volume limit without selecting a different schedule. `ArchiveSplitSavePipeline` factors the existing begin → W → validation → publish sequence out of the session. `ArchiveSplitWorkProducer` still verifies assembled input before replay and uses join + updater for byte-split ZIP, with M5's rewrite fallback. M2 remains the only split publisher.

Immediate split `willPublish` never captures an undo slot. Successful publication calls `finishMutation(nil, published: true)` (which invokes `recordMutation(nil)`) and clears the document's undo registrations. Proven rollback leaves the original set editable and retryable; both proven immediate rollbacks and held failures clear obsolete undo and require recovery. Their immediate-mode wording does not claim that the temporary edit remains pending. The document retains its original gate URL spelling; URL equality for following moves resolves symlinks.

## Save As

The existing accessory grid gains fixed-height split controls only for Save As: None; Same as Original (saved schedule or inferred S) for a numbered source; or custom number + KB/MB/GB with the shared 64 KiB minimum validator. Sources with a saved schedule or inferred uniform S default to Same as Original; single-file and unconfigured uneven sources default to None. Disabled custom controls retain their layout space, and the existing encryption resize/animation machinery is unchanged. New Archive has no split row.

Both modes use `ArchiveCreationController` and `ArchiveCreationTransaction`. Split output uses `VolumeSetTarget(parent:newSetScheme:schedule:…)` with no old layout. Names are `<chosen archive name>.001`, `.002`, etc.; ZIP is a byte split of an ordinary ZIP. M2 checks estimated names before producing W, then checks the actual full plan and next name before splitting and publication. Occupied names produce the specified refusal and are never replaced. A late collision also preserves the foreign file.

Save As uses a single cancellable streaming input snapshot in `ArchiveSplitWorkProducer` for numbered sources and the same verified rewrite implementation for single-file sources. None from a split source produces an ordinary single archive. Deferred Save As includes its pending plan, preserves all original volumes and switches the same document to the new gate or ordinary file. Returned destination URLs retain the user's spelling. Native metadata and AppleDouble app-owned metadata follow the corrected M5 rules: quarantine is on the actual volumes; cache failures are post-commit warnings. Save As carries these warnings into the document notice.
