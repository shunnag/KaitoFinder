macOS 27.2 / Apple Silicon / Sparkle 2.10.0で確認した。

## 再現と変更

修正前は、署名済みReleaseからZIPを作成した後にリリースノートの拡張子を検査していた。
`.rst` を指定するとエラーになり、出力先にはZIPと検証用マーカーが残った。
同じ出力先での再実行は「既に存在する」として拒否された。
この実署名ビルドでの再現は次に保存している。

`build/UpdatePreparationVerification/b068e030-2816-434a-9aee-dda17fdee593/before-fix.txt`

- ノートの形式と存在は、ZIP作成より前に検査する。
- 出力先の親に作業用ディレクトリを作り、コード署名・Sparkle署名・フィード内容の検証を完了する。
- 最後に同じボリューム上でディレクトリを確定する。失敗・通常の中断時は作業用ディレクトリを削除する。
- 既存の出力先は、壊れたシンボリックリンクも含めて拒否する。アプリ内部への出力も拒否する。
- 確定直前に別の処理が出力先を作った場合も、空ディレクトリを含めて保持する。

確定にはmacOSの `renamex_np` と `RENAME_EXCL` を使う。
Xcode SDKの `<sys/stdio.h>` の宣言・定数と、Appleの
[排他的renameの公開資料](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming)
を確認した。機能を利用できない場合はエラーとして終了し、上書きする方法には切り替えない。
強制終了や電源断では作業用ディレクトリが残る場合があるため、通常の例外・中断処理とは区別する。
