## Implementation and release-note draft

Immediate imports, new archive creation, conversion imports, and deferred save replay now use
GyoshukuKit's batch addition API. Small input files can be prefetched within the library's bounded
window. Entries retain their planned order. Progress and item completion continue through the
P6 ledger; conversion offsets imported slots by the number of pending additions.

Replay retains removal → rename → encryption reservation → addition → folder order, saved directory
dates and owner-ID dispatch. Its additions and folders share one batch. Ledger-free replay still
counts one unit per completed addition/folder, including split production.

`willStart` checks both Progress and Task cancellation before the existing file hook. `didFinish`
updates the ledger before `didProcess`. Imports and creation retain item-path attribution for the
smallest failed index; creation preserves the existing RewriterError/password mapping. Replay
rethrows the underlying error. Callback failures retain their original type and identity, even when
the callback itself throws an ArchiveAdditionError from another operation. ArchiveErrorText has a
fallback for unhandled batch errors and preserves the caller's localization bundle.

Release-note draft: small-file imports and archive creation use batch source prefetch. Error messages
for changed prefetched sources consistently name the source path. File order, progress item counts,
and cancellation/publication boundaries are preserved. Timing acceptance is recorded separately;
this text does not claim an AC-A5 speed result.
