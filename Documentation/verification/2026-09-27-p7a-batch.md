## Implementation and release-note draft

Immediate imports, new archive creation, conversion imports, and deferred save replay now use
GyoshukuKit's batch addition API. Small input files can be prefetched within the library's bounded
window. Entries retain their planned order. Progress and item completion continue through the
P6 ledger; conversion offsets imported slots by the number of pending additions.

Replay retains removal → rename → encryption reservation → addition → folder order, saved directory
dates and owner-ID dispatch. Its additions and folders share one batch. Ledger-free replay still
counts one unit per completed addition/folder, including split production.

`willStart` checks both Progress and Task cancellation before the existing file hook. `didFinish`
updates the ledger before `didProcess`. Imports and creation retain item-path attribution for the
smallest failed index; creation preserves the existing RewriterError/password mapping. Replay
rethrows the underlying error. Callback failures retain their original type and identity, even when
the callback itself throws an ArchiveAdditionError from another operation. ArchiveErrorText has a
fallback for unhandled batch errors and preserves the caller's localization bundle.

Release-note draft: small-file imports and archive creation use batch source prefetch. Error messages
for changed prefetched sources consistently name the source path. File order, progress item counts,
and cancellation/publication boundaries are preserved. Timing acceptance is recorded separately;
this text does not claim an AC-A5 speed result.

## S41 correction 1

The orchestrator reported a successful normal-host build-for-testing, followed by 310 tests in
16 related classes and a 1,698-test full run. Both runs exposed the S41 regression in
`LHAUpdateDeferredSaveTests.testFiveChangesAndRenameOnlyPreserveReservedOrderAndFolderDate`:
the non-mixed, rename-only case committed with `.splice` instead of `.inPlacePatch`.
Those host runs were performed by the orchestrator, not by this correction run.

Replay called `add(_:events:)` even when its combined additions/folders array was empty.
At the required GyoshukuKit `244a9c2` pin, that call prepares LHA's append writer and changes
its rename-only commit route. KaitoFinder now skips empty batches explicitly at all three
boundaries: `ArchiveSaveReplayPlan.replay`, `ArchiveImportTransaction.run`, and the creation
transaction's shared writer/rewriter helper. Replay still validates and applies/counts edits
and reserves encryption before returning. Import retains source verification. Creation and
publication retain their finish/commit and final ledger accounting. This does not depend on
a future GyoshukuKit empty-batch fix.

Three tests were added to `BatchImportTests`:

- `testRenameOnlyDeferredSaveDoesNotCallBatchInAnyUpdater` wraps each real ZIP, tar, tar.gz,
  7z and LHA updater at the replay boundary and records batch calls. Each format runs both
  with and without the ledger, then completes commit, verification and publication. It checks
  zero batch calls, one rename credit, completed progress, projected names and preserved contents.
  The explicit call observation remains effective if GyoshukuKit later accepts empty batches.
- `testCreationWithoutImportedItemsKeepsProgressAndContents` checks conversion without imports
  into all seven formats and creation of an empty ZIP, including item counts and final progress.
- `testEmptyImportLeavesArchiveAndProgressUntouched` checks the five updater formats, preserving
  the original bytes and incoming progress and producing no publication identity or work files.
