## API と UI 接続

```swift
ArchiveCapabilities.inspect(url:format:) -> ArchiveCapabilities
ArchiveSession.capabilities: ArchiveCapabilities
ArchiveSession.append(urls:to:progress:didProcess:willPublish:) throws -> ArchiveImportResult
ArchiveDocument.append(urls:to:progress:) async throws -> ArchiveImportResult
ArchiveDropTarget.folder(for:) -> String
ArchiveDropTarget.node(for:in:) -> EntryNode?
ArchiveDropTarget.accepts(capabilities:offersCopy:hasFiles:busy:) -> Bool
ArchiveImportPlan.build(urls:folder:existing:progress:) throws -> ArchiveImportPlan
ArchiveImportTransaction.run(plan:archive:progress:didProcess:willPublish:) throws -> ArchiveImportResult
ArchiveViewState.resolve(in:)
ArchiveIncomingPasteboard.canPaste(_:)
ArchiveIncomingPasteboard.representation(_:)
ArchiveIncomingPasteboard.readDrop(_:)
ArchiveIncomingPasteboard.readPaste(_:)
```

`ArchiveSession` は actor。重い列挙・圧縮・commit をその actor 上で直列に実行し、
UI へは Sendable な結果だけを返す。`didProcess` と `willPublish` は同じ worker 上の
検証用 phase hook であり、通常の UI は指定しない。

書庫 open 時に updater の検査を実行し、`ArchiveCapabilities` を一つ保持する。
append だけが true になり得る。非 ZIP、SFX、trailing data、不正な CD offset、
書き込み権限不足を区別する。門番の enum と原文の理由を保存し、
メニューの tooltip とウインドウ下部で制限を表示する。
可否が false の drop は `[]` を返し、drop highlight を設定しない。

outline は `NSFilePromiseReceiver.readableDraggedTypes` と `.fileURL` を登録する。
カーソル下の行を値型の解決処理へ渡し、フォルダならその中、ファイルなら親、
空白なら root を選び、`setDropItem(..., dropChildIndex: NSOutlineViewDropOnItemIndex)` を呼ぶ。
仮想フォルダにも同じ規則を適用する。受理する操作は `.copy` のみ。

promise は NSURL より先に照会・読み取りする。`receivePromisedFiles` は
`acceptDrop` の同期呼出し中に開始し、Task 内から開始しない。
SDK の契約に従い、同じ drag の receiver は同じ一時ディレクトリを使う。
`fileNames` は receive の呼出し後に件数を得る（呼出し前は空、`fileTypes` の件数は
legacy promise では信用できない）。callback が先着しても通知数を失わない。
取消し時も供給元の callback が残っている間は一時領域を保持する。

Cmd-V は実行時にだけ `.general` の file URL を読む。メニュー検証では
`canReadObject` のみを使い、`readObjects` は呼ばない。型の probe と読み取りを
`ArchivePasteboardSource` で分離したため、この順序はサービスなしの XCTest で確認できる。
現在の UI は書庫全体を表示する outline なので、paste 先の「表示フォルダ」は root。
選択している行を paste 先として解釈しない。フォルダ行への drop ではそのフォルダを使う。

## 追加・失敗・取消しの境界

1. 追加元を `lstat` で列挙し、ディレクトリを再帰、リンクはリンク自身として扱う。
   新規名は NFC へ正規化する。既存 entry と中間の仮想フォルダ、同じ操作内の名前、
   ファイルとディレクトリの衝突、表示上の先頭 `./` も検査する。
   不正な追加先や traversal は拒否する。フォルダを既存フォルダへ黙って併合しない。
2. 事前検査では後続の追加元も調べ、項目ごとの理由を集める。
   一つでも失敗なら、その操作全体を原本に反映しない。
   writer が失敗すると instance が再利用不能になるので、書き込み段階の失敗は
   そのパスを報告して作業コピーを破棄する。
3. 原本の隣に mode 0700 の作業ディレクトリを作り、`copyItem` で書庫を複製する。
   updater の `add` と `commit` はこの作業コピーに対して行う。
   各ディレクトリは `addDirectory`、ファイル・リンクは `add(contentsOf:as:)` を使う。
   ディレクトリまで `add(contentsOf:)` に渡すと writer 自身が再帰し、二重追加と
   取消し粒度の悪化を招くため使わない。
4. updater の commit 完了と作業コピーの reader open 成功を待ち、取消しと原本の
   inode / size / mode / mtime / ctime を確認する。同一ボリュームの `rename` 一回で公開する。
   公開前の取消し・失敗は原本の byte を変更しない。公開後は取り消されたとは報告しない。
5. session 内で await を挟まず世代を進め、**`ArchiveReader.open(url:)` を新しく呼ぶ**。
   `reopen()` で置換後の byte を読む実装にはしていない。展開用 reader の複製には
   引き続き `reopen()` を使うが、これは現在の世代の primary reader からだけ行う。
6. document は Quick Look / Open の materialization controller を閉じて cache を無効化し、
   新しい entry tree を表示する。選択、展開、先頭表示行を path で復元する。
   公開後の再読み込みに失敗した場合は generation を進めたまま旧 reader の要求を拒否し、
   `ArchiveImportResult.reloadFailure` で「追加済みだが再読み込み失敗」と区別して知らせる。

アプリ側の作業コピーは意図的に必要である。GyoshukuKit の設計・実装には
**`commit()` が置換後の属性復元で失敗する場合がある**と明記されている。
その失敗を原本へ持ち込まないため、ライブラリ内部の clone に加えて外側の一時コピーを置いた。
ライブラリの commit 後の取消し・失敗も、公開前なら原本が byte-identical であることを検査した。
原本の POSIX mode、quarantine、任意 xattr、作成日時の保持も XCTest で確認した。

Cancel は受信待ち・列挙中・項目間・commit 前後で確認する。GyoshukuKit の同期 API 自体には
取消し hook がないため、一つの大きいファイルの圧縮や copy / commit 呼出しの途中では
即時停止せず、その呼出しが戻った時点で中止する。原本はその間も変更しない。
ディレクトリ entry の属性は `addDirectory` の既定値（mode 0755、現在日時）。
ファイル属性は `add(contentsOf:)` の既存動作で保存する。

## 実行コマンドと制限

指定された通常の二つのコマンドはユーザーキャッシュへの書き込みを sandbox に拒否される。
キャッシュと DerivedData を repo 内に移すとビルドできるが、app-hosted test は
`com.apple.testmanagerd.control` / 分散通知のサービス制限により起動できない。
そのため、生成した同じテストバンドルを XCTest runner で直接実行した。
Swift の `-disable-sandbox` は manifest / compiler の子プロセス用で、この実行環境の
filesystem / サービスの制限を解除するものではない。

```sh
CFFIXED_USER_HOME="$PWD/build/User" \
XDG_CACHE_HOME="$PWD/build/Cache" \
CLANG_MODULE_CACHE_PATH="$PWD/build/ModuleCache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/build/ModuleCache" \
xcodebuild -project KaitoFinder.xcodeproj -scheme KaitoFinder \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath build/DerivedData \
  -clonedSourcePackagesDirPath build/SourcePackages \
  -IDEPackageSupportDisableManifestSandbox=YES \
  'OTHER_SWIFT_FLAGS=$(inherited) -disable-sandbox' clean build
```

同じ設定で `-testLanguage en -testRegion US test` も試し、test bundle の生成後に
サービス制限で止まることを記録した。通常の bundle 生成だけなら `build-for-testing` を使える。
直接実行は次のとおり。

```sh
umask 022
env -i PATH=/usr/bin:/bin TMPDIR="$TMPDIR" \
  CFFIXED_USER_HOME="$PWD/build/User" \
  DYLD_INSERT_LIBRARIES="$PWD/build/DerivedData/Build/Products/Debug/KaitoFinder.app/Contents/MacOS/KaitoFinder.debug.dylib" \
  /Applications/Xcode.app/Contents/Developer/usr/bin/xctest \
  "$PWD/build/DerivedData/Build/Products/Debug/KaitoFinder.app/Contents/PlugIns/KaitoFinderTests.xctest"
```

> **Verification: drag in / paste in (2026-09-10)**
>
> Starting at e5d9088, M2 adds files and directory trees to ZIP archives through a
> second local SwiftPM package, `../../GyoshukuKit`, linked statically. Neither
> library repository was changed. Delete, rename and attribute-editing verbs remain
> unavailable. The arm64 clean build succeeds with zero Swift compiler warnings;
> the unused-AppIntents metadata tool warning remains distinct from compiler warnings.
>
> One capability value is computed at document open and refreshed after mutation.
> Format refusals and each updater gatekeeper retain their specific reason. Paste
> enablement and drop acceptance use it; an unwritable archive never receives a
> drop highlight. Folder rows target themselves, file rows their parent, and empty
> space the root, including synthesized folders. Only copy is accepted. The current
> outline displays the archive root, which is the paste destination regardless of
> selection. Drops can target nested folders.
>
> Promise receivers take precedence over URLs. Receipt begins synchronously inside
> acceptDrop, all receivers in a drag share their destination, and fileNames are
> counted after calling receive rather than before it. The SDK notes that legacy
> fileTypes counts need not match file counts. The temporary directory outlives
> outstanding producer callbacks even after cancellation. Paste reads real file URLs
> only on execution; validation checks types without reading objects. A source spy
> proves validation and representation ordering without any pasteboard service.
>
> Import planning recursively enumerates directories without following symlinks,
> normalizes names to NFC, and rejects traversal and collisions with existing files,
> explicit or virtual folders, display-normalized leading-dot names, and other items
> in the same operation. Planning continues to collect per-source failures. Any
> failure leaves the entire operation unpublished; a poisoned writer is never reused.
>
> The app uses an additional same-volume working copy because GyoshukuKit explicitly
> permits commit to fail during metadata restoration after its internal replacement.
> All updater operations therefore affect only this working copy. After commit and
> a successful reader-open check, cancellation and original identity are checked;
> one rename publishes the prepared archive. Tests prove original-byte preservation
> on cancellation and writer failure, including failures after the staged commit.
> Quarantine, POSIX mode, a custom xattr and creation date survive publication.
>
> Commit and fresh reload are serialized within ArchiveSession with no intervening
> await. Generation advances, ArchiveReader.open(url:) obtains new bytes, and stale
> promises resolve by path. The control reader really does miss the appended entry
> when reopened, proving the fixture distinguishes the old-inode trap. The document
> invalidates materialization caches and restores selection, expansion and scroll
> anchor by path. A post-publication reload error is reported as added-but-not-reloaded,
> never as an unchanged or cancelled archive.
>
> Progress cancellation is checked while receiving, enumerating, between entries,
> and before and after commit. GyoshukuKit has synchronous calls without cancellation
> hooks, so a large individual compression/copy/commit call must return before the
> app can stop; the original stays unchanged until publication. Directory entries
> use addDirectory defaults (0755 and the current time); disk-file attributes use
> the writer's existing behavior.
>
> The suite contains the existing 73 tests plus 25 DragInTests listed above: 98 tests,
> zero failures, five service-probe skips. All 24 new core tests run; the new named
> pasteboard adapter test is the only new skip. Old skips are the two pasteboard
> tests, folder-provider UTI test, and Open With discovery test. Tiny tar, PE-prefixed
> ZIP, trailing-data ZIP, and patched-EOCD ZIP fixtures exercise actual refusal paths,
> and gatekeeper fixtures remain listable. SFX/trailing payloads are also compared;
> the artificial offset=1 fixture specifically asserts KaitoKit’s existing local-header/CD
> overlap error on extraction. File and directory updates pass unzip -t
> and KaitoKit byte comparisons. Service skips do not carry core assertions.
>
> Literal requested build/test commands cannot write default caches. Workspace-cache
> builds work, but app-hosted tests cannot access testmanagerd, so the built bundle
> runs directly under XCTest. This does not claim all 73 existing test bodies ran or
> that normal xcodebuild test succeeded. An alternate preference directory still reported
> ja-JP; a genuinely English-preferred hosted run is not claimed. Refusal assertions use
> stable enums rather than translated UI text. Real Finder drag-in, real Cmd-V, Photos/Mail/
> Safari promise drags, legacy callbacks, visible highlights/expansion/scroll state,
> and actual progress/Cancel clicks could not be verified here. Physical macOS 26,
> real >4 GiB updates, power loss, actual disk-full/metadata-syscall failure injection,
> concurrent external editing and every Finder-tag/ACL variant also remain unverified.
> There is an identity check before publication but no added cross-process lock.
