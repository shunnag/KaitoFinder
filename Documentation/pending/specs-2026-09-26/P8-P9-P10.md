## P8（KaitoFinder）: 検索の絞り込みを速くし、大きな木では MainActor の外で計算する

### 計測から決めたこと

- 狭い検索語と一致しない検索語では、MainActor の時間の 95–99 % が `EntryTreeFilter.init`（EntryTree.swift:199-229）で、
  その大半は一致しない名前ごとの Foundation の比較（:216-217、約 1.1–1.3 µs / 名、日本語の名前は約 1.9 µs / 名）。
  → 印字可能 ASCII 同士の照合を byte の走査にする（P8-a、100 倍以上）。結果は変えない。
- 漢字・仮名・ハングルの文字を含む検索語は、印字可能 ASCII だけの名前には Foundation でも一致しない（0.3 (d2)）。この組は最も遅い
  （500k で 1.1 s）。→ Foundation を呼ばずに不一致と決める（P8-a2）。結果は変えない。
- 日本語の名前は Foundation の比較のままなので、500k では数百 ms かかり続ける。
  → 大きな木（`root.nodeCount >= 20,000`）の空でない検索語は MainActor の外で計算する（P8-b）。

### DESIGN

#### D1 照合（P8-a・P8-a2）

```swift
/// 検索語と名前の照合。印字可能 ASCII の名前は byte で決め、それ以外は従来の Foundation の比較にする。
nonisolated struct EntryNameMatcher: Sendable {
    let query: String
    private let foldedQuery: [UInt8]?     // 検索語が空でない印字可能 ASCII のときだけ。A–Z を a–z にした byte 列
    private let rejectsASCIINames: Bool   // 検索語が D1 の範囲の Lo を一つでも含む

    init(query: String)
    func matches(_ name: String) -> Bool
}
```

- `foldedQuery`: `query.utf8` の全 byte が 0x20...0x7E のときだけ作る（A–Z は `| 0x20`）。一つでも外れれば nil（全角・日本語・濁点付き・
  制御文字を含む検索語は ASCII の名前にも Foundation で照合する。全角の検索語が ASCII の名前に一致する `.widthInsensitive` の規則を保つため）。
- `rejectsASCIINames`: `query.unicodeScalars` に、一般カテゴリが `.otherLetter` で、次の範囲にある scalar が一つでもあれば true:
  U+3040–30FF、U+3400–4DBF、U+4E00–9FFF、U+AC00–D7A3、U+F900–FAFF、U+FF66–FF9F、U+20000–3134F。
  範囲内でも Lo でない scalar（U+3099・U+309A の結合濁点、U+30FC の長音、U+FF9E・U+FF9F など）は数えない。
- `matches`:
  1. `name.utf8.withContiguousStorageIfAvailable` で byte を得る。得られなければ Foundation（`name.range(of: query, options:
     [.caseInsensitive, .diacriticInsensitive, .widthInsensitive]) != nil`、:216-217 と同じ options）。遅延 bridge の NSString の名前で
     黙って Foundation に戻らないよう、`EntryNode.init`（EntryTree.swift:38-45）で `var name = name; name.makeContiguousUTF8()` してから保持する
     （native の String では何もしない。照合のたびに写さない）。
  2. 名前の **全 byte** が 0x20...0x7E であることを先に確かめる。外れる byte があれば Foundation（名前の途中の結合文字などで
     Foundation の結果が変わり得るので、ASCII の部分で一致を見つけても早く返さない）。
  3. 名前が印字可能 ASCII だけのとき: `foldedQuery` があれば、名前の各 byte を同じ規則で畳みながら部分一致を探す（素朴な走査でよい。
     `memchr` で先頭 byte を探してもよい）。`foldedQuery` が無く `rejectsASCIINames` なら false。どちらでもなければ Foundation。
- 空の検索語では呼ばれない（`EntryTreeFilter` の :203-210 の早い return のまま）。
- 印字可能に限る理由: CR・LF・NUL・DEL・TAB を含む名前は、Foundation の合成文字の扱い（CRLF など）に任せる。
- DEBUG: `nonisolated static let decidedWithoutFoundationForTesting = TaskLocal<ArchiveTestCounter?>(wrappedValue: nil)`。3 で Foundation を
  呼ばずに決めた回数を数える（bridge された NSString の名前などで黙って Foundation に戻っていないことを AC-a3 で確かめる）。

### DESIGN

1. 読み取り: `threads(forKey:)` は `NSNumber` で、`CFBooleanGetTypeID` でなく、整数（`doubleValue == Double(intValue)`）で、`0` か `1...64` の
   ときだけその値、それ以外は 0。setter は範囲外を 0 にして保存する（`clampedLevel` のように近い値へ丸めない。自動に戻すのが安全）。
   setter は全キーの保存の後に `didChange` を一度だけ出す（:146-147 のまま）。
2. `writerOptions(for:)`: S13 の後の `return switch format { … }` を `var options: WriterOptions = switch format { … }` にし、
   `if compressionThreads != 0 { options.compressionThreads = compressionThreads }`、`return options`。他の値は S13 の後のまま。
   7z / LHA の「他形式の設定を持ち込まない」方針（:51-53 のコメント）は、並列数が全形式に共通の設定なので例外とし、コメントをそう改める。
3. popup の上限: `max(hardware.processors, 保存値)`。コア数を越える保存値（別の Mac から移した設定）はそのまま表示・使用する（GK は 1...64 を受ける）。
4. 注記: 表示する並列数 t は、選択が自動なら `hardware.automaticCompressionThreads`、それ以外は選択値。見積り `estimatedLZMA2Memory(threads: t)` を
   `ByteCountFormatter`（`countStyle = .memory`）で文字列にして 1 文目に入れる。`見積り > hardware.memory / 4` なら 2 文目を足し、
   `textColor = .systemOrange`、それ以外は `.secondaryLabelColor`（色だけでなく 2 文目の文で伝える）。設定の変更（`didChange`）と popup の選択で更新する。
5. `ArchiveSession.verify` の自動値の置き換えは、結果の値を変えない（同じ式）。

1. KaitoFinder だけ。GyoshukuKit の public API を増やさない（`resolvedCompressionThreads` を public にしない）。

#### DESIGN

**A1 表示の根**

- `displayedRoot` は保存する値で、`filterQuery.isEmpty ? currentFolder : root` を代入する場所を次の二つに限る（init の初期値を除く）。どちらも
  `collapseItem(nil, collapseChildren: true)` の**後**（P8 の D5 の規則）:
  1. `reloadFilteredEntries`: collapse と `filterQuery` の切替の後、`entryFilter` の差し替えの前。`display()`（:760）・検索の適用・隠しファイルの
     切替・`relocateCurrentFolder` はここを通る。
  2. `navigate`（A2 の 5）: collapse の後。
  計算型（`filterQuery.isEmpty ? currentFolder : root`）にすると、検索語の適用や `currentFolder` の変更の直後の collapse が新しい根の子を辿り、
  画面の行を閉じられない。`currentFolder` と `filterQuery` は collapse の前に変えてよいが、`displayedRoot` は変えない。
- `children(of: nil)` は `displayedRoot` の子。`sortedChildren` の cache は node の identity が key なので、そのまま使える。
- `outlineView.parent(forItem:)` は最上位の行で nil を返し、それは `displayedRoot` を意味する。今日の `viewStateAfterRemoving`（:1374-1400）は
  nil の親の兄弟を `children(of: nil)` で得るので、`displayedRoot` の子になり、そのまま正しい。`selectEnclosingFolder`（`.expand` のときだけ使う）も
  最上位では何もしない。
- 新規 `outlineAncestors(of node:) -> [EntryNode]?`: `displayedRoot` の直下から node の親までの列。node が `displayedRoot` の真の子孫でなければ
  （`displayedRoot` 自身を含む）nil。`pathNodes(to:)`（:798-807）は書庫の最上位からの列のまま（パスバー用）。
- `restoreViewState`（:1455-1474）: `resolved.expanded`・`resolved.selected`・`resolved.collapsed`・`resolved.top` のうち、`outlineAncestors(of:)` が nil の
  node（表示の根の外と表示の根そのもの）には `expandItem`・`collapseItem`・選択・scroll をしない。選択の祖先の展開（:1459-1461）と
  `selectPathItem`（:858-860）は `outlineAncestors` を使う。`expandedPaths` には表示の根の path が入ることがある（`renameCreatedFolder` の
  :1138-1141、`startMove` の :1305-1306 が親の path を足す）ので、この規則が要る。
- `captureViewState`（:1435-1453）: 今日どおり `root.directoryNodes` を走査する（表示の根の外の node は行ではないので展開状態は false になる）。
  `hiddenExpandedPaths` の扱いは変えない。

**A2 移動**

`navigate(to node: EntryNode, selecting: EntryNode? = nil, history: History)`（`History`: `.push`（新しい移動）、`.back`、`.forward`）:

1. `guard !operationInFlight, !isLocked, node.isDirectory, node が self.root の部分木（parent を辿って self.root に着く）,
   showsHiddenFiles || !node.isHidden`。改名中なら `guard outlineView.commitRenaming()`。
2. `requestedFilterQuery` か `filterQuery` が空でなければ `setFilterQuery("")`（同期。P8 の D3）。
3. `node === currentFolder` なら（2 の後、検索は空）、選択を外して先頭へスクロールし、履歴を変えずに終わる（パスバーで現在のフォルダを
   押したときなど。同じ path を stack に積まない）。
4. `folderViewStates[currentFolderPath] = captureViewState()`。履歴: `.push` なら `backStack.append(currentFolderPath)`（100 件を越えたら古い方から
   捨てる）、`forwardStack.removeAll()`。`.back` なら `forwardStack.append(currentFolderPath)`、`.forward` なら `backStack.append(currentFolderPath)`。
5. `closePreview()`、`outlineView.cancelPendingClickRename()`、`outlineView.collapseItem(nil, collapseChildren: true)`（古い根の行で閉じる）、
   `currentFolder = node`、`currentFolderPath = node.path`、`displayedRoot = node`（2 で検索は空）、`sortedChildren` はそのまま、
   `outlineView.reloadData()`。
6. 表示状態: `.back` / `.forward` なら `folderViewStates[node.path]` があればそれを `restoreViewState`。無ければ、または `.push` なら、
   `selecting` があればその行を選んで見える位置へ、無ければ選択なしで先頭へスクロール。
7. `updatePathControl()`、`window?.toolbar?.validateVisibleItems()`。DEBUG の `navigationObserver`（`nonisolated static let … TaskLocal`）に
   `(from, to, history)` を出す。

操作:

- `goBack`: `backStack` から path を取り出し、`directoryNode(at:)`（下）で解決できるまで取り出し続ける（解決できない path は捨てる）。
  解決できれば `navigate(to:history: .back)`、無ければ `NSSound.beep()`。`goForward` も同じ。
- `goToEnclosingFolder`: `.enter` なら `currentFolder !== root` のとき `navigate(to: currentFolder.parent!, selecting: currentFolder, history: .push)`。
  `.expand` なら今日の `selectEnclosingFolder()`。
- `openEntry`（:1982-1986）: `.enter` で、選択がちょうど一つのフォルダだけなら `navigate(to: そのフォルダ, history: .push)`。
  それ以外（ファイルを含む選択、複数のフォルダ、`.expand`）は今日どおり（選んだフォルダを展開し、ファイルを開く）。
- `doubleClickEntry`（:1970-1980）: `.enter` でクリックした行がフォルダなら `navigate(to:history: .push)`。それ以外は今日どおり。
- パスバーの表示（`updatePathControl` :809-827）: `components = pathNodes(to: selectedNodes.first ?? displayedRoot)`（書庫の最上位からの列。
  選択が無ければ現在のフォルダまで、検索中で選択が無ければ書庫の項目だけ）。
- パスバーのクリック（`selectPathItem` :852-865）: 書庫の項目（`representedObject` が nil）は、`.enter` で `currentFolder !== root` なら
  `navigate(to: root, selecting: 現在のフォルダの最上位の祖先, history: .push)`、それ以外は今日どおり選択を外す。node の項目は、
  node が現在のフォルダかその祖先なら（検索中でなければ）`navigate(to: node, selecting: 現在のフォルダへ向かう子（node が現在のフォルダなら nil）, history: .push)`
  （現在のフォルダなら A2 の 3 で履歴を積まない）。それ以外（表示の根の部分木の中）は今日どおり選択する（祖先の展開は `outlineAncestors` で）。
- `.expand` のときは、ダブルクリック・⌘↓・⌘O・⌘↑・パスバーが今日の動作と同じになり、現在のフォルダは常に書庫の最上位で、
  戻る・進むは無効（履歴が空）。設定を `.enter` から `.expand` に変えたら、`relocateCurrentFolder(to: root)`（下）と履歴・`folderViewStates` の消去を行う。
- `relocateCurrentFolder(to node:)`（利用者の移動ではない付け替え。A3 と `.expand` への切替で使う）: 検索を消さず、履歴も
  `folderViewStates` も変えない。`currentFolder = node`、`currentFolderPath = node.path` だけを変え、検索中（`filterQuery` が空でない）なら
  それで終わる（表示の根は `root` のまま）。検索中でなければ、状態を取り、`reloadFilteredEntries(restoring:expandsMatches: false)` で
  閉じてから根を切り替える（A1 の 1）。

`directoryNode(at path: String) -> EntryNode?`: path が空なら `root`。それ以外は `root.nodes(at: path).first(where: \.isDirectory)`
（EntryTree.swift:131-140）で、node が隠しで、適用中の `showsHiddenFiles` が偽なら nil。

**A3 書庫が変わったとき**

- `display(_:…)`: `self.root = root`（:703）の後、`reloadFilteredEntries`（:760）の前に `resolveCurrentFolder()`:
  `currentFolderPath` の component を末尾から一つずつ除きながら `directoryNode(at:)` を試し、最初に見つかった node にする（最後は `root`）。
  見つかった path が元と違えば `currentFolderPath` を更新し、DEBUG の observer に `.fellBack(from:to:)` を出す。履歴と `folderViewStates` は変えない
  （解決できない path は、使うときに捨てる）。表示の根は `reloadFilteredEntries` が決める（A1 の 1）。
- `displayLocked`（:523）: `currentFolder = root`、`currentFolderPath = ""`、履歴と `folderViewStates` を消す。
- 隠しファイルを表示しなくなったとき: 適用中の `showsHiddenFiles` を偽にする箇所（P8 の D5 `applyFilter` と D6 の同期の経路）で、状態を取った後、
  現在のフォルダかその祖先が隠しなら、表示される最も近い祖先を `currentFolder` にする（`displayedRoot` はその後の `reloadFilteredEntries` が決める）。
  `folderOpening` の変更は A2 の末尾のとおり。
- 改名・移動で現在のフォルダかその祖先の path が変わる場合: `startEdit`（:1220）と `startMove`（:1268）の開始時に `currentFolderPath` を覚え、
  公開に成功した後（:1248-1253、:1296-1316 の `result.published` の枝）、`viewStateAfterRenaming` / `viewStateAfterMoving` と同じ
  `ArchivePath.replacingPrefix` で新しい path を求める。元と違い、`directoryNode(at:)` で解決できれば、`relocateCurrentFolder(to:)` でそこへ移し、
  `backStack`・`forwardStack`・`folderViewStates` の key も同じ写しで書き換える（`display()` はこの時点で既に古い path を最も近い祖先へ解決して
  いるので、ここで正しいフォルダへ戻す。検索中の結果から祖先を改名した場合に起きる）。取り消し・やり直しでは追従しない（決めたこと #9）。

**A4 追加の先と、存在しないフォルダの拒否**

- `dropFolder(nil)`（:1497-1499）と `dropDecision`（:1504-1520）の `ArchiveDropTarget.folder(for:)` に `blankArea: displayedFolder` を渡す
  （空白への local move が「同じ場所」の判定に表示している場所を使う）。`ArchiveDropTarget.node(for:in:)`（:32-41）は、nil の行では今日どおり
  nil（表全体の強調）。
- `newFolder`（:1096）: 空白のメニューからは `displayedFolder`、それ以外は選択の最初の行のフォルダ、選択が無ければ `displayedFolder`
  （今日は `ArchiveDropTarget.folder(for: nil)` = 書庫の最上位）。
- `paste`（:1479-1482）は同期なので、その時点の `displayedFolder`。
- `addFiles`（:1484-1495）: パネルを開く前に `let folder = displayedFolder` を取り、完了の closure ではその値を使う（今日は完了の時点の
  `self.displayedFolder` を読むので、パネルを開いている間の再読込で、見ていたフォルダと違う先へ追加し得る）。DEBUG の
  `addFilesPanelForTesting` があれば、パネルを出さずにそれを呼び、同じ完了の処理（取った `folder` で `startImport`）を渡す。
- `startImport`（:1567）と `newFolder` の開始時: `folder` が空でなく `directoryNode(at: folder)` が nil なら、編集を始めずに
  `reportImportFailure`（新規フォルダは `reportEditFailure`）で既存の文言 `追加先フォルダが見つからないか、ファイルと衝突しています: %@。`
  を出す。モデルの拒否（ArchiveImportPlan.swift:58-61、ArchiveNewFolderPlan.build の ArchiveImportTransaction.swift:386、
  移動の ArchiveImportTransaction.swift:158）はそのまま残る最後の安全網。
