# KaitoFinder 0.9.0

小さなファイルが多い 7z・RAR5 の書庫を開く・展開する・検証する速度を大きく改善し、.xz・zstd・LZMA の復号と LZMA 方式の圧縮も高速化しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.14.0 / GyoshukuKit 0.11.0 / Sparkle 2.10.0 を同梱。

## 改善（速さ）

- 小さなファイルが多い 7z（ファイルごとに圧縮したもの）と RAR5 で、後に続く項目を複数コアで先に復号しておくようになりました。並列数と保持するメモリは、Mac の有効な論理 CPU 数・物理メモリ（既定で半分まで）・設定の「電力の使用方針:」に従います。
- 単独の .xz と tar.xz を、KaitoKit 自身の高速な LZMA2 復号で読み取るようになりました。
- 7z の LZMA / LZMA2、lzip、zstd、RAR5 の復号を高速化しました。単一スレッドでの処理も速くなりました。
- LZMA 方式の圧縮（7z の LZMA、ZIP の LZMA、.lzma、.lz、圧縮レベルを指定した .xz と 7z の LZMA2）を高速化しました。圧縮結果のバイト列は従来と同じです。

KaitoKit 0.14.0 の高速化を反映しました。以下は MacBook（Apple M4 Max・16 コア・128 GiB）で、KaitoKit CLI（`kaito sha --sink`）を使ってそれぞれの書庫の全項目を最後まで読み取り、KaitoKit 0.13.0（KaitoFinder 0.8.0 の同梱版）と 0.14.0 を比較した例です。それぞれ 3 回の最短時間を使い、読み取ったバイト列は同一です。所要時間は内容・設定・環境によって変わります（[MacBook 復号性能の比較計測](https://github.com/shunnag/KaitoKit/blob/v0.14.0/Documentation/verification/2026-10-11-decode-performance.md)）。

- 小ファイル 50,000 件の 7z（ファイルごとに圧縮）は約 7.0 倍、RAR5 は約 4.2 倍（BLAKE2 チェックサム付きは約 4.7 倍）高速になりました。
- 256 MiB のテキストの RAR5 は約 1.4 倍、単一ブロックの tar.xz は約 1.2 倍、複数ブロックの .xz は約 1.3 倍高速になりました。
- zstd は約 1.2 倍、tar.lz と 7z（solid）は約 1.1 倍高速になりました。

圧縮は、32 MiB のテキストを圧縮レベル 6 で圧縮したとき、7z の LZMA・ZIP の LZMA・.lzma で所要時間が約 0.7 倍、.xz で約 0.74 倍になりました（GyoshukuKit 0.10.0 との比較）。

## 変更

LZMA2 の規格に反する特定のデータ並び（辞書をリセットする非圧縮チャンクの直後に、プロパティを持たない LZMA チャンクが続くもの）を、7-Zip や xz と同じく壊れたデータとして扱うようになりました。

## English

Made opening, extracting, and verifying 7z and RAR5 archives with many small files much faster, and sped up .xz, zstd, and LZMA decoding as well as LZMA compression. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.14.0 / GyoshukuKit 0.11.0 / Sparkle 2.10.0.

### Faster decoding and compression

- For 7z archives that compress each file separately and for RAR5 archives with many small files, upcoming entries are now decoded ahead of time on multiple cores. Parallelism and the memory held follow the Mac's active logical CPU count, physical memory (up to half by default), and the “Power usage:” setting.
- Standalone .xz and tar.xz files are now read with KaitoKit's own fast LZMA2 decoder.
- Sped up decoding for 7z LZMA / LZMA2, lzip, zstd, and RAR5. Single-threaded processing is faster too.
- Sped up LZMA compression (LZMA in 7z and ZIP, .lzma, .lz, and .xz / 7z LZMA2 with an explicit compression level). Compressed bytes are unchanged.

Includes speed improvements from KaitoKit 0.14.0. These examples were measured on a MacBook with an Apple M4 Max (16 cores, 128 GiB), reading every entry of each archive to the end with the KaitoKit CLI (`kaito sha --sink`). They compare KaitoKit 0.13.0 (included in KaitoFinder 0.8.0) with 0.14.0, using the best of 3 runs for each. Decoded bytes were identical. Times vary with content, settings, and environment ([MacBook decoding benchmark record](https://github.com/shunnag/KaitoKit/blob/v0.14.0/Documentation/verification/2026-10-11-decode-performance.md)).

- A 7z with 50,000 small files compressed separately was about 7.0× faster, and RAR5 about 4.2× (about 4.7× with BLAKE2 checksums).
- RAR5 with 256 MiB of text was about 1.4× faster, single-block tar.xz about 1.2×, and multi-block .xz about 1.3×.
- zstd was about 1.2× faster, and tar.lz and solid 7z about 1.1×.

For compression, 32 MiB of text at level 6 took about 0.7× the time for LZMA in 7z and ZIP and for .lzma, and about 0.74× for .xz (compared with GyoshukuKit 0.10.0).

### Changed

A specific LZMA2 sequence that violates the format (an LZMA chunk without properties right after an uncompressed chunk that resets the dictionary) is now treated as corrupt data, as 7-Zip and xz do.
