# KaitoFinder 0.6.0

作成・変換・編集で使える圧縮形式と設定を増やし、圧縮を高速化しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.12.1 / GyoshukuKit 0.8.0 / Sparkle 2.10.0 を同梱。

## 追加

- tar.zst / tar.lz / tar.lzma / tar.lz4 / tar.br / tar.Z の作成・形式変換と、追加・削除・改名・置換に対応しました。これらの形式は編集時に全体を再圧縮します。
- 保存パネルと設定で、ZIP に BZip2 / LZMA / XZ / Zstandard / PPMd、7z に LZMA / Deflate / BZip2 / PPMd、LHA に lh6 / lh7 を選べるようになりました。編集にも使えます。既定は引き続き ZIP が Deflate、7z が LZMA2、LHA が lh5 です。
- 圧縮レベルは LZMA 系が 0〜9、Deflate・BZip2・LHA・PPMd が 1〜9、Zstandard が 1〜19（標準 3）。ZIP（Zstandard 以外）・7z・LHA には「圧縮しない」もあります。tar.lz4 / tar.br / tar.Z はレベルを選べません。方式とレベルは形式ごとに設定へ保存します。
- 7z にソリッド圧縮（既定オフ）とフィルタ（なし / 自動 / x86 (BCJ) / ARM64 / Delta）を追加しました。ソリッドブロック内の項目を削除すると、そのブロックを再圧縮します。
- 通常ファイル 1 個を選んだとき、保存パネルの「1 ファイルの圧縮」で .gz / .bz2 / .xz / .zst / .lz / .lzma / .lz4 / .br / .Z を作れます。元の名前と拡張子を残します（例: report.pdf.gz）。新規作成専用で、開いた後の編集には対応しません。

ZIP の BZip2 / LZMA / XZ / Zstandard / PPMd は macOS のアーカイブユーティリティや unzip では開けない場合があります。選択時に互換性の注記を表示します。

## 改善（速さ）

GyoshukuKit 0.8.0 の圧縮処理の高速化を反映しました。以下は Mac mini M4・12 スレッドで測った、開発中の基準版との比較例です。所要時間は内容・設定・環境によって変わります。

- 256 MiB の混在入力では、ZIP Zstandard が約 11.2 倍、ZIP PPMd が約 4.8 倍、ZIP XZ が約 3.9 倍、LHA LH7 が約 3.7 倍高速になりました（[比較計測](https://github.com/shunnag/GyoshukuKit/blob/v0.8.0/Documentation/verification/2026-10-08-integrated-mini-ab.md)）。
- 単一の 10 MiB ファイルを ZIP / 7z の BZip2 で圧縮する例では、約 5 倍高速になりました（[BZip2 の比較計測](https://github.com/shunnag/GyoshukuKit/blob/v0.8.0/Documentation/verification/2026-10-08-bzip2-splice-mini-ab.md)）。

## 修正

- 小さい画面で保存シートの暗号化をオンにして表示が広がったとき、「保存」「キャンセル」が画面外へ押し出される問題を修正しました。
- 中断した分割アーカイブの保存を回復するとき、接続ボリュームの確認不足で保留した場合は、ログに未確認のボリュームの場所と理由を記録するようになりました。

## English

Expanded compression formats and settings for creation, conversion, and editing, and made compression faster. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.12.1 / GyoshukuKit 0.8.0 / Sparkle 2.10.0.

### Added

- Create, convert, and edit tar.zst / tar.lz / tar.lzma / tar.lz4 / tar.br / tar.Z archives, including adding, deleting, renaming, and replacing items. Editing these formats recompresses the entire archive.
- The save panel and Settings now offer BZip2 / LZMA / XZ / Zstandard / PPMd for ZIP, LZMA / Deflate / BZip2 / PPMd for 7z, and lh6 / lh7 for LHA. These methods also apply to editing. Defaults remain Deflate for ZIP, LZMA2 for 7z, and lh5 for LHA.
- Compression levels are 0–9 for LZMA-based methods, 1–9 for Deflate / BZip2 / LHA / PPMd, and 1–19 for Zstandard (default 3). ZIP (except Zstandard), 7z, and LHA also offer no compression. tar.lz4 / tar.br / tar.Z have no selectable level. Methods and levels are saved in Settings for each format.
- Added 7z solid compression (off by default) and filters (None / Auto / x86 (BCJ) / ARM64 / Delta). Deleting an item inside a solid block recompresses that block.
- Selecting one regular file enables “Single-file compression” in the save panel for .gz / .bz2 / .xz / .zst / .lz / .lzma / .lz4 / .br / .Z. The original name and extension are kept (for example, report.pdf.gz). This is for new files only; editing after opening is unsupported.

ZIP archives using BZip2 / LZMA / XZ / Zstandard / PPMd may not open in macOS Archive Utility or unzip. A compatibility note appears when selecting these methods.

### Faster compression

Includes compression improvements from GyoshukuKit 0.8.0. These examples compare development baselines on a Mac mini M4 using 12 threads. Times vary with content, settings, and environment.

- With 256 MiB of mixed input, ZIP Zstandard was about 11.2× faster, ZIP PPMd 4.8×, ZIP XZ 3.9×, and LHA LH7 3.7× ([benchmark record](https://github.com/shunnag/GyoshukuKit/blob/v0.8.0/Documentation/verification/2026-10-08-integrated-mini-ab.md)).
- Compressing one 10 MiB file with BZip2 in ZIP / 7z was about 5× faster ([BZip2 benchmark record](https://github.com/shunnag/GyoshukuKit/blob/v0.8.0/Documentation/verification/2026-10-08-bzip2-splice-mini-ab.md)).

### Fixed

- Fixed Save and Cancel being pushed offscreen when enabling encryption expands the save sheet on a small display.
- When recovery of an interrupted split-archive save is held because some mounted volumes could not be checked, the logged reason now identifies their locations and why they could not be checked.
