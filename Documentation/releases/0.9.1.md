# KaitoFinder 0.9.1

ファイルを書庫へ追加するときに、内容が変わっていないのに「変更されました」と表示されて追加できないことがある問題を修正しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.14.1 / GyoshukuKit 0.11.0 / Sparkle 2.10.0 を同梱。

## 修正

- Finder からドラッグしたファイルなどを開いている書庫へ追加すると、「確認中に追加元が変更されました。もう一度追加してください」と表示されて追加できないことがある問題を修正しました。macOS がファイルの付加情報（最後に使った日時やアクセス許可の記録など）を書き込むと、内容と変更日は同じでもファイルの属性変更時刻が更新され、それを内容の変更と誤って判定していました。内容・サイズ・変更日・別のファイルへの差し替えは引き続き検出します。
- 取り消し・やり直しでも、同じ付加情報の書き込みを書庫の変更と誤って判定しないようにしました。
- 小さなファイルが多い RAR5 の書庫を 1 項目ずつゆっくり読むと、先に復号した内容を必要以上にメモリに保持することがある問題を修正しました（KaitoKit 0.14.1）。

## English

Fixed an issue where adding files to an archive could fail with a “changed” error even though the files had not changed. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.14.1 / GyoshukuKit 0.11.0 / Sparkle 2.10.0.

### Fixed

- Adding files to an open archive, for example by dragging them from Finder, could fail with “A source item changed while it was being checked. Add it again.” When macOS writes file metadata (such as the last-used date or access-permission records), the file's attribute-change time is updated even though its contents and modification date stay the same, and this was mistaken for a content change. Changes to contents, size, or modification date, and replacement with a different file, are still detected.
- Undo and redo no longer mistake the same kind of metadata write for a change to the archive.
- Fixed excessive memory use when reading RAR5 archives with many small files one entry at a time, where already decoded entries could be kept in memory longer than needed (KaitoKit 0.14.1).
