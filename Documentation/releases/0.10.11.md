# KaitoFinder 0.10.11

不正な LZ4 ファイルを開いたときの無駄な処理を修正しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.22.1 / GyoshukuKit 0.18.0 / Sparkle 2.10.1 を同梱。

## 修正

- **不正な LZ4 ファイルの検証を早く打ち切るようにしました。** 0.10.10 は並列検証で不正なブロックを見つけた後も残りのブロックを処理し、その間はキャンセルも効きませんでした。最初の失敗で残りの検証を止め、キャンセルもブロックごとに確認します。約 248 MiB の不正なファイルを Mac mini M4 で測定すると、約 1.1 秒かかっていた失敗までの時間が 0.06 秒になりました。表示されるエラーは同じで、正常な LZ4 ファイルの展開速度に一貫した変化はありません。

操作方法、編集・保存の仕組みは 0.10.10 と同じです。測定条件の詳細は KaitoKit の [codec 性能・安定性検証](https://github.com/shunnag/KaitoKit/blob/v0.22.1/Documentation/verification/2026-11-05-codec-performance.md)に記録しています。

## 既知の問題

- 開いているアーカイブを Finder などで名称変更・移動すると、そのウインドウでプレビュー・クイックルック・展開が
  できなくなることがあります。以前の版からある問題で、ウインドウを開き直すと直ります。今後の版で修正します。
- アプリのコーデック辞書の上限は既定で 1 GiB です。物理メモリが 32 GiB 以上の Mac では「設定… › パフォーマンス」の「展開の辞書上限」で 8 GiB を選べます（展開とパスワード確認は直列になります）。RAR5 compression version 1 の書庫のうち、選択した上限を超える実確保量が必要なものは展開できません。
- custom RAR VM、RAR 1.3 / 1.4 の Data からの継続巻解決・ASCII 以外の password、CAB Quantum は引き続き未対応です。

## English

Fixes wasted work when opening a malformed LZ4 file. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.22.1 / GyoshukuKit 0.18.0 / Sparkle 2.10.1.

### Fixes

- **Validation of a malformed LZ4 file now stops early.** After finding a bad block, 0.10.10 still processed the remaining blocks during parallel validation, and cancellation did not take effect in the meantime. Validation now stops at the first failure and checks for cancellation at every block. With a malformed file of about 248 MiB on Mac mini M4, the time to fail dropped from about 1.1 seconds to 0.06 seconds. The reported error is unchanged, and valid LZ4 files show no consistent change in decoding speed.

The user interface and editing / saving model are unchanged from 0.10.10. See KaitoKit’s [codec performance and stability record](https://github.com/shunnag/KaitoKit/blob/v0.22.1/Documentation/verification/2026-11-05-codec-performance.md) for measurement details.

### Known issues

- After an open archive is renamed or moved in Finder or elsewhere, preview, Quick Look and extraction in its window
  may stop working. This problem predates this version; reopening the window fixes it. It will be fixed in a future version.
- The app's codec dictionary limit is 1 GiB by default. On a Mac with at least 32 GiB of physical memory, you can select 8 GiB under Settings > Performance > Extraction dictionary limit (extraction and password verification then run serially). RAR5 compression version 1 archives that need a larger allocation than the selected limit cannot be extracted.
- Custom RAR VM programs, continuation of RAR 1.3 / 1.4 volumes from Data, non-ASCII passwords for these old archives, and CAB Quantum remain unsupported.
