# KaitoFinder 0.7.0

Mac のコアをより活用して圧縮を高速化し、並列処理の電力設定を追加しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.12.1 / GyoshukuKit 0.9.0 / Sparkle 2.10.0 を同梱。

## 追加

- 設定の「圧縮」に「電力の使用方針:」を追加しました。既定は「低電力モードで並列数を減らす」です。「低電力モードや高温時に並列数を減らす」「常にすべてのコアを使う」も選べます。次に始める圧縮・展開・パスワード検証に適用します。
- 「速さを優先する（圧縮率がわずかに下がります）」を追加しました（既定オフ）。オンにすると、ZIP の XZ・Zstandard、7z、単独の XZ・lzip など、対応する方式をコア数の多い Mac で高速化できます。圧縮率はわずかに下がり、出力サイズが増えます。
- 「圧縮の並列数:」の明示指定の対応範囲を 1〜64 から 1〜1024 に広げました。設定の選択肢は通常 Mac の論理 CPU 数までで、それを超える保存済みの値も保持します（最大 1024）。

並列数を明示した圧縮・パスワード検証では、電力設定による削減を行いません。展開は圧縮の並列数の指定とは別に電力設定に従います。

## 改善（速さ）

- 圧縮の並列数が「自動」のとき、従来の最大 8 コアから、通常は Mac のすべての有効な論理 CPU を使うようになりました。物理メモリの GiB 数や圧縮方式のメモリ制限に応じて並列数を減らし、選択した電力設定にも従います。
- 並列展開の最大 8 ワーカーの制限をなくしました。処理量や独立した項目の数、メモリ・電力設定に応じて、より多くのコアを使えます。

GyoshukuKit 0.9.0 の高速化を反映しました。以下は MacBook（Apple M4 Max・16 コア）で、アプリの一括追加経路を使って 256 MiB の混在入力を圧縮し、従来の既定 8 スレッドと新しい既定の全コア使用を比較した例です。出力バイト列は同一です。所要時間は内容・設定・環境によって変わります（[MacBook A/B 比較計測](https://github.com/shunnag/GyoshukuKit/blob/v0.9.0/Documentation/verification/2026-10-09-cpu-scaling-macbook-ab.md)）。

- ZIP Deflate は約 5.7 倍、7z Copy＋フィルタは約 7.5 倍高速になりました。
- 7z LZMA2 のソリッド圧縮は約 2.2 倍高速になりました。
- ZIP Zstandard と tar.gz は約 1.9 倍、LHA LH7 は約 1.8 倍高速になりました。
- BZip2（ZIP / 7z / tar.bz2）は約 1.6〜1.7 倍高速になりました。
- ZIP LZMA は約 1.4 倍、ZIP PPMd と XZ は約 1.3 倍高速になりました。

単一の 10 MiB ファイルの XZ 圧縮では、「速さを優先する」をオンにすると、オフの 0.79 秒から 0.22 秒に短縮しました（[同じ比較計測の記録](https://github.com/shunnag/GyoshukuKit/blob/v0.9.0/Documentation/verification/2026-10-09-cpu-scaling-macbook-ab.md)）。

## 修正

- 単独の .bz2 ファイルを、単一の bzip2 ストリームで作成するようになりました（GyoshukuKit 0.9.0）。通常ファイル 1 個を選び、保存パネルの「1 ファイルの圧縮」で .bz2 を選ぶと作成できます。

## English

Made compression faster by using more of the Mac's cores, and added power settings for parallel processing. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.12.1 / GyoshukuKit 0.9.0 / Sparkle 2.10.0.

### Added

- Added “Power usage:” to Settings > Compression. The default is “Reduce threads in Low Power Mode.” You can also choose “Reduce threads in Low Power Mode or when hot” or “Always use all cores.” This applies to the next compression, extraction, or password verification operation.
- Added “Prefer speed (slightly larger archives)” (off by default). Turning it on speeds up supported methods, including ZIP XZ / Zstandard, 7z, and standalone XZ / lzip, on Macs with many cores. The compression ratio is slightly lower, producing larger files.
- Expanded the supported explicit “Compression threads:” range from 1–64 to 1–1024. Settings normally offers values up to the Mac's logical CPU count and retains a higher saved value, up to 1024.

An explicit thread count bypasses power-based reductions for compression and password verification. Extraction follows the power setting independently of the compression thread count.

### Faster compression

- Automatic compression now normally uses all active logical CPUs on the Mac, replacing the previous limit of 8. Parallelism remains limited by physical memory in GiB and compression method memory limits, and follows the selected power setting.
- Removed the 8-worker cap on parallel extraction. It can use more cores when the workload, independent entries, memory, and power setting allow it.

Includes speed improvements from GyoshukuKit 0.9.0. These examples were measured on a MacBook with an Apple M4 Max (16 cores), compressing 256 MiB of mixed input through the app's batch-add path. They compare the previous default of 8 threads with the new default of all cores. Output bytes were identical. Times vary with content, settings, and environment ([MacBook A/B benchmark record](https://github.com/shunnag/GyoshukuKit/blob/v0.9.0/Documentation/verification/2026-10-09-cpu-scaling-macbook-ab.md)).

- ZIP Deflate was about 5.7× faster, and 7z Copy+filter about 7.5×.
- 7z LZMA2 solid compression was about 2.2× faster.
- ZIP Zstandard and tar.gz were about 1.9× faster, and LHA LH7 about 1.8×.
- BZip2 (ZIP / 7z / tar.bz2) was about 1.6–1.7× faster.
- ZIP LZMA was about 1.4× faster, and ZIP PPMd and XZ about 1.3×.

For a single 10 MiB file compressed as XZ, enabling “Prefer speed (slightly larger archives)” reduced the time from 0.79 seconds with the option off to 0.22 seconds ([same benchmark record](https://github.com/shunnag/GyoshukuKit/blob/v0.9.0/Documentation/verification/2026-10-09-cpu-scaling-macbook-ab.md)).

### Fixed

- Standalone .bz2 files are now created as a single bzip2 stream (GyoshukuKit 0.9.0). Select one regular file and choose .bz2 under “Single-file compression” in the save panel to create one.
