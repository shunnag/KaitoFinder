# KaitoFinder 0.4.0

フォルダへの移動と表示オプションを追加し、大きなアーカイブの編集や、多数のファイルの圧縮・展開を改善しました。macOS 26 以降、Apple Silicon 専用。

## 新機能

- アーカイブ内のフォルダへ移動し、その中身を表示できます。「戻る」（⌘[）、「進む」（⌘]）、「内包フォルダ」（⌘↑）と、パスバーからの移動に対応しました。
- 「表示オプションを表示」（⌘J）から、並べ順、列の表示、アイコンと文字の大きさを変更できます。
- 一覧のヘッダのメニューと「表示 > 列」で、表示する列を選べます。圧縮率・CRC-32・アクセス権・格納順の列と、「フォルダを常に先頭に表示」を追加しました。
- 設定の「圧縮の並列数」で、自動または指定した数を選べます。7z・tar.xz の圧縮に使うメモリ量の目安も表示します。

## 改善（速さ）

KaitoKit 0.11.0 / GyoshukuKit 0.6.0 の改善を反映しました。以下の数値は開発時の比較計測の例です。所要時間はアーカイブの内容や環境によって変わります。

- 大きな ZIP の読み込み・編集・保存を高速化しました。50 万件の ZIP で 1 件を改名する計測では約 3.0 秒から約 1.9〜2.0 秒、5 件の変更をまとめて保存する計測では約 5.2 秒から約 2.5 秒になりました。
- 単一ファイルの tar・LHA・7z では、対応する書庫の変更していないデータを保って編集し、書き直す量を減らしました。7z の改名はヘッダの更新だけで行い、ソリッドブロックの一部を削除するときは、そのブロックを再圧縮します。
- tar.gz・tar.bz2・tar.xz は、対応する区切りごとに編集し、変更していない部分の再圧縮を減らしました。他のツールで作られた書庫などは、最初の編集で全体を再圧縮する場合があります。
- 多数の小さなファイルの取り込み・作成で先読みを並列に行います。5 万件の ZIP 作成の計測では、書き込み部分が約 2.4 秒から約 1.0 秒になりました。圧縮の並列処理とメモリ使用量も見直しました。
- 大きなアーカイブの検索中も一覧を操作できます。英数字の名前 50 万件を絞り込む計算は、計測例で約 0.6 秒から約 0.06 秒になりました。大量の検索結果を表示する時間は別にかかります。
- Zstandard（zstd）の展開を高速化し、tar.zst の読み込みや Zstandard 圧縮の ZIP の展開を改善しました。複数項目の展開も並列化し、サムネイルは表示中の行を優先して読み込みます。
- 対応する ZIP・7z では、パスワードの設定・変更・削除で本文を再圧縮しなくなりました。暗号化された ZIP の編集前のパスワード確認も並列に行います。
- 大きな書庫を開く間の読み込み表示とキャンセルを改善し、一覧を早く表示するようにしました。短い処理では進捗シートの表示を抑え、分割アーカイブの保存では重複していた読み取りとハッシュ計算を減らしました。
- フォルダ項目の記録がない ZIP をドラッグで展開したときのアクセス権や、名前の先頭に `./` がある場合の衝突表示、保存時モードで開いた直後の表示順を修正しました。

## 変更と注意

- フォルダのダブルクリック・⌘↓・⌘O は、既定でそのフォルダへ移動します。設定 > 一般 >「フォルダを開くとき」を「その場で展開」にすると、従来の階層一覧を広げる操作に戻せます。
- tar・tar.gz・tar.bz2・tar.xz・7z・LHA に追加する項目は、既定で末尾に入ります。設定 > 一般 >「追加した項目の位置」を「先頭（編集のたびに全体を書き直す）」にすると従来の先頭へ追加する動作に戻ります。この場合は全体を書き直し、圧縮 tar・7z・LHA は全体を再圧縮します。ZIP は常に末尾です。
- tar と圧縮 tar の変更しない項目は、既定で名前や所有者 ID（uid / gid）を保ちます。設定 > 圧縮 >「変更しない項目の所有者ID」を「0に戻す（編集のたびに全体を書き直す）」にすると、従来の所有者 ID の扱いに戻せます。「追加するファイルの所有者ID(uid / gid)を保存」は、ディスクから追加する項目のための別の設定です。全体を書き直す経路では、名前も従来どおり正規化される場合があります。
- tar 系の名前に含まれる `\` と先頭の `C:` を、展開・ドラッグ・コピー・プレビューでそのまま保ちます。以前は `\` をフォルダの区切りとして扱い、先頭の `C:` を取り除いていました。展開先の外へ出るパスの拒否は続けます。
- LHA の改名した項目は level 2 ヘッダになります。非 ASCII の名前があり、書庫全体の文字コードを推定できない LHA は、最初の編集で全体を CP932 の名前へ書き直します。
- 7z の anti 項目（削除を表す項目）は、編集後も anti 項目として保ちます。以前は空のファイルに変わっていました。
- 元の全項目が属性を持たない、空ではない 7z には、7zz と同様に追加項目にも属性を付けません。この場合、追加するファイルの Unix アクセス権も保存されません。一部だけ暗号化された 7z では既存項目の暗号化状態を保ち、追加項目は現在のパスワードで暗号化します。
- APFS 以外で単一ファイルの 7z を部分更新する場合、書庫ファイル自身の Finder タグなどの拡張属性は引き継ぎません。アクセス権と作成日は復元します。分割 7z の扱いは従来どおりです。
- 小さなファイルが多い tar.xz は、編集を速くするための圧縮の区切りの変更により、計測例では約 5〜12 % 大きくなります。
- 分割保存の検証データの一部は、書庫全体のハッシュから、各巻のハッシュをまとめた値へ意味が変わりました。保存形式は維持しており、互換性の記録では旧版・新版は互いが保存したセットを受け入れられます。各巻の内容の検証は引き続き行います。分割セットは今回も全巻を書き直します。
- 取り込み・作成・編集の進捗バーは、処理するバイト量に応じて進みます。処理した項目数は「n / N項目」として別に表示します。
