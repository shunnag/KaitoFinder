# KaitoFinder 0.8.0

書庫を開く・展開する・検証するときの復号を高速化し、Mac のコアをより活用するようにしました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.13.0 / GyoshukuKit 0.10.0 / Sparkle 2.10.0 を同梱。

## 改善（速さ）

- 単独の .xz / .bz2、複数 frame の zstd、lzip の複数 member、DMG（UDIF）の chunk を、自動で複数コアを使って復号するようになりました。並列数は Mac の有効な論理 CPU 数・物理メモリ（既定で半分まで）・設定の「電力の使用方針:」に従います。展開されるバイト列は並列数によらず同じです。
- 「電力の使用方針:」が、圧縮・展開の並列数に加えて、書庫の読み取り時の自動の復号並列数にも適用されるようになりました（既定「低電力モードで並列数を減らす」）。
- Deflate64、RAR5、PPMd、LZ4、zstd、AES 暗号化 7z / ZIP の復号と、RAR5 の BLAKE2 チェックサム計算を高速化しました。単一スレッドでの処理も速くなりました。

KaitoKit 0.13.0 の高速化を反映しました。以下は MacBook（Apple M4 Max・16 コア・128 GiB）で、KaitoKit CLI（`kaito sha --sink`）を使ってそれぞれの書庫の全項目を最後まで読み取り、KaitoKit 0.12.1（KaitoFinder 0.7.0 の同梱版）と 0.13.0 を比較した例です。それぞれ 3 回の最短時間を使い、読み取ったバイト列は同一です。所要時間は内容・設定・環境によって変わります（[MacBook 復号性能の比較計測](https://github.com/shunnag/KaitoKit/blob/v0.13.0/Documentation/verification/2026-10-10-decode-performance.md)）。

- 単独の .xz（256 MiB のテキスト）は約 9.8 倍、.bz2 は約 8.9 倍高速になりました。
- 8 frame の zstd は約 4.5 倍、tar.lz4 は最大約 3.7 倍高速になりました。
- DMG は ULFO 約 3.9 倍、UDBZ 約 3.5 倍、ULMO 約 2.3 倍高速になりました。
- Deflate64 の ZIP は最大約 3.3 倍、AES 暗号化 7z は最大約 3.3 倍高速になりました。
- 小ファイル 50,000 件の RAR5 は約 2.0〜2.3 倍高速になりました。
- PPMd の 7z は約 1.5 倍、ZIP は約 1.3 倍、tar.bz2 は約 1.3〜1.5 倍高速になりました。

## 変更

GyoshukuKit 0.10.0 は KaitoKit 0.13.0 と CPU 構成の判定を共有します。圧縮の結果や設定に変更はありません。

## English

Made decoding faster when opening, extracting, and verifying archives by using more of the Mac's cores. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.13.0 / GyoshukuKit 0.10.0 / Sparkle 2.10.0.

### Faster decoding

- Standalone .xz / .bz2 files, zstd with multiple frames, lzip with multiple members, and DMG (UDIF) chunks now decode automatically using multiple cores. Parallelism follows the Mac's active logical CPU count, physical memory (up to half by default), and the “Power usage:” setting. Decoded bytes are identical regardless of the thread count.
- “Power usage:” now also applies to automatic decoding parallelism when reading archives, alongside compression and extraction parallelism. The default is “Reduce threads in Low Power Mode.”
- Sped up decoding for Deflate64, RAR5, PPMd, LZ4, zstd, and AES-encrypted 7z / ZIP, as well as BLAKE2 checksum calculation in RAR5. Single-threaded processing is faster too.

Includes speed improvements from KaitoKit 0.13.0. These examples were measured on a MacBook with an Apple M4 Max (16 cores, 128 GiB), reading every entry of each archive to the end with the KaitoKit CLI (`kaito sha --sink`). They compare KaitoKit 0.12.1 (included in KaitoFinder 0.7.0) with 0.13.0, using the best of 3 runs for each. Decoded bytes were identical. Times vary with content, settings, and environment ([MacBook decoding benchmark record](https://github.com/shunnag/KaitoKit/blob/v0.13.0/Documentation/verification/2026-10-10-decode-performance.md)).

- Standalone .xz (256 MiB of text) was about 9.8× faster, and .bz2 about 8.9×.
- zstd with 8 frames was about 4.5× faster, and tar.lz4 up to about 3.7×.
- DMG was about 3.9× faster for ULFO, 3.5× for UDBZ, and 2.3× for ULMO.
- Deflate64 ZIP was up to about 3.3× faster, and AES-encrypted 7z up to about 3.3×.
- RAR5 with 50,000 small files was about 2.0–2.3× faster.
- PPMd 7z was about 1.5× faster, ZIP about 1.3×, and tar.bz2 about 1.3–1.5×.

### Changed

GyoshukuKit 0.10.0 shares CPU configuration detection with KaitoKit 0.13.0. Compression results and settings are unchanged.
