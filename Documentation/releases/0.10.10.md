# KaitoFinder 0.10.10

書庫の展開と、一部の形式の圧縮を高速化しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.22.0 / GyoshukuKit 0.18.0 / Sparkle 2.10.1 を同梱。

## 改善

- **LZ4 の展開がさらに速くなりました。** 独立ブロックの文法と展開後サイズを並列に検証し、小さなブロックをまとめて展開します。ブロックが 4〜64 KiB の 64 MiB のデータでは、M4 Max / Mac mini M4 とも 0.10.9 の 2.2〜2.6 倍の速さです。
- **LHA 書庫の LArc 方式の展開を高速化しました。** `-lzs-` の画像データは約 1.8 倍の速さになり、`-lz5-` の画像データは時間を約 7% 短縮しました。
- **PPMd と CAB LZX の展開を改善しました。** 文書の ZIP PPMd（variant I）は約 16%、7z PPMd（variant H）は約 8%、実 product.cab の LZX は約 6% 短縮しました。
- **古い RAR の展開を高速化しました。** RAR 2.0 の LZ データは大きな書庫（biglz）の測定で約 1.7 倍の速さになり、RAR 1.5 の文書・音声データは約 15〜28% 短縮しました。
- **LHA（lh5）、tar.Z / .Z、BZip2 の圧縮を改善しました。** lh5 は Mac mini M4 の text / binary で約 5〜19% 速くなり、長い一致が見つかる入力ではさらに 5〜15% 改善しました。LZW は Mac mini M4 で約 0.4〜4.5% の改善で、M4 Max では ±1% 前後です。BZip2 は同じバイトの連続が多い入力で約 3〜5% 短縮しました。いずれも作成される書庫の内容は変更前と同じバイト列です。

測定は固定の入力によるもので、書庫の内容により効果は異なります。操作方法、編集・保存の仕組みは 0.10.9 と同じです。測定条件の詳細は KaitoKit の [codec 性能・安定性検証](https://github.com/shunnag/KaitoKit/blob/v0.22.0/Documentation/verification/2026-11-05-codec-performance.md)と GyoshukuKit の [encoder 性能・安定性検証](https://github.com/shunnag/GyoshukuKit/blob/v0.18.0/Documentation/verification/2026-11-05-encoder-performance.md)に記録しています。

## 既知の問題

- 開いているアーカイブを Finder などで名称変更・移動すると、そのウインドウでプレビュー・クイックルック・展開が
  できなくなることがあります。以前の版からある問題で、ウインドウを開き直すと直ります。今後の版で修正します。
- アプリのコーデック辞書の上限は既定で 1 GiB です。物理メモリが 32 GiB 以上の Mac では「設定… › パフォーマンス」の「展開の辞書上限」で 8 GiB を選べます（展開とパスワード確認は直列になります）。RAR5 compression version 1 の書庫のうち、選択した上限を超える実確保量が必要なものは展開できません。
- custom RAR VM、RAR 1.3 / 1.4 の Data からの継続巻解決・ASCII 以外の password、CAB Quantum は引き続き未対応です。

## English

Faster archive extraction and faster compression for some formats. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.22.0 / GyoshukuKit 0.18.0 / Sparkle 2.10.1.

### Improvements

- **LZ4 decoding is faster again.** Independent blocks are validated in parallel for grammar and decoded size, and small blocks are decoded together. With 64 MiB of data in 4–64 KiB blocks, it is 2.2–2.6 times as fast as 0.10.9 on both M4 Max and Mac mini M4.
- **LArc methods in LHA archives decode faster.** `-lzs-` image data is about 1.8 times as fast, and `-lz5-` image data takes about 7% less time.
- **PPMd and CAB LZX decoding improved.** ZIP PPMd (variant I) on documents takes about 16% less time, 7z PPMd (variant H) about 8% less, and LZX on a real product.cab about 6% less.
- **Legacy RAR decoding is faster.** RAR 2.0 LZ data is about 1.7 times as fast on a large archive (biglz), and RAR 1.5 documents and audio take about 15–28% less time.
- **LHA (lh5), tar.Z / .Z, and BZip2 compression improved.** lh5 is about 5–19% faster for text and binary on Mac mini M4, with a further 5–15% where long matches occur. LZW improves by about 0.4–4.5% on Mac mini M4 and stays within about ±1% on M4 Max. BZip2 takes about 3–5% less time on input with many repeated bytes. Created archives stay byte-for-byte identical to before.

Measurements use fixed inputs; results vary with archive content. The user interface and editing / saving model are unchanged from 0.10.9. See KaitoKit’s [codec performance and stability record](https://github.com/shunnag/KaitoKit/blob/v0.22.0/Documentation/verification/2026-11-05-codec-performance.md) and GyoshukuKit’s [encoder performance and stability record](https://github.com/shunnag/GyoshukuKit/blob/v0.18.0/Documentation/verification/2026-11-05-encoder-performance.md) for measurement details.

### Known issues

- After an open archive is renamed or moved in Finder or elsewhere, preview, Quick Look and extraction in its window
  may stop working. This problem predates this version; reopening the window fixes it. It will be fixed in a future version.
- The app's codec dictionary limit is 1 GiB by default. On a Mac with at least 32 GiB of physical memory, you can select 8 GiB under Settings > Performance > Extraction dictionary limit (extraction and password verification then run serially). RAR5 compression version 1 archives that need a larger allocation than the selected limit cannot be extracted.
- Custom RAR VM programs, continuation of RAR 1.3 / 1.4 volumes from Data, non-ASCII passwords for these old archives, and CAB Quantum remain unsupported.
