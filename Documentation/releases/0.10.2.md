# KaitoFinder 0.10.2

多数のアーカイブを同時に開いても、開けるファイル数の上限に達しないようにしました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.15.0 / GyoshukuKit 0.12.0 / Sparkle 2.10.0 を同梱。

## 修正

- 多数のアーカイブを開いたままにすると、アーカイブごとにファイルを開いたままにしていたため、開けるファイル数の上限（通常 256）に達して、ほかのアーカイブや保存が失敗することがある問題を修正しました。使っていないアーカイブのファイルはアプリ全体で 64 本までに抑え、内容を読むときに開き直します。開いている間にアーカイブが差し替えられた場合は、別のファイルとして読まずにエラーにします。
- 分割アーカイブの巻の確認中に起きた読み取りエラーを、「破損」や「巻が見つからない」ではなく、読み取りエラーとして表示するようにしました（KaitoKit 0.15.0）。
- 7z アーカイブの更新で、多数のフォルダ（圧縮単位）を再圧縮または暗号化しなおすときに、フォルダの数だけ一時ファイルを開いていたため、上限に達して失敗することがある問題を修正しました（GyoshukuKit 0.12.0）。

## English

Opening many archives at once no longer runs out of open files. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.15.0 / GyoshukuKit 0.12.0 / Sparkle 2.10.0.

### Fixed

- Each open archive kept its file open, so with many archives open the app could reach the open-file limit (usually 256) and fail to open other archives or save. Idle archive files are now limited to 64 for the whole app and reopened when needed. If an archive is replaced while open, KaitoFinder reports an error instead of reading the new file.
- Read errors while checking the volumes of a split archive are now reported as read errors, not as a damaged archive or a missing volume (KaitoKit 0.15.0).
- Updating a 7z archive that re-compresses or re-encrypts many folders (compression units) opened one temporary file per folder and could reach the open-file limit. This is fixed (GyoshukuKit 0.12.0).
