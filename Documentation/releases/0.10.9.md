# KaitoFinder 0.10.9

関連付けから開くときの扱いと、書庫の展開性能を改善しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.21.0 / GyoshukuKit 0.16.0 / Sparkle 2.10.1 を同梱。

## 改善

- **関連付けから開くときにウェルカムスクリーンを表示しません。** 「起動時にようこそウインドウを表示」の設定がオンでも、Finder の関連付けから書庫を開いたときは、起動時のようこそを表示しません。すでに表示されている場合は閉じます。書庫を開く処理自体は従来どおりです。
- **LZ4 の展開を並列化しました。** 独立ブロックの文法と実出力長を検証してから並列に展開します。M4 Max / Mac mini M4 の固定書庫で、text は baseline の 0.8686 / 0.7664 倍、50,000 個の小ファイルは 0.9400 / 0.8979 倍になりました。
- **Deflate64 を高速化しました。** bit 状態と Huffman 表を見直し、ZIP / 7z の測定で baseline の約 0.92〜0.93 倍になりました。
- **CAB LZX を大幅に高速化しました。** 実 product.cab（106 ファイル）で、baseline の 0.4535 / 0.4386 倍になりました。
- **RAR15 の solid 展開も改善しました。** 状態バッファを固定長化し、single thread で baseline の 0.7778 / 0.7340 倍になりました。

操作方法、編集・保存の仕組みは 0.10.8 と同じです。対応形式や測定条件の詳細は KaitoKit の [decode 性能・安定性検証](https://github.com/shunnag/KaitoKit/blob/v0.21.0/Documentation/verification/2026-11-03-decode-performance.md)に記録しています。

## 既知の問題

- 開いているアーカイブを Finder などで名称変更・移動すると、そのウインドウでプレビュー・クイックルック・展開が
  できなくなることがあります。以前の版からある問題で、ウインドウを開き直すと直ります。今後の版で修正します。
- アプリのコーデック辞書の上限は 1 GiB です。RAR5 compression version 1 の書庫のうち、これを超える実確保量が必要なものは
  現行のアプリ設定では展開できません。KaitoKit の API で上限を引き上げた場合の対応であり、アプリ側の上限緩和は今後の課題です。
- custom RAR VM、RAR 1.3 / 1.4 の Data からの継続巻解決・ASCII 以外の password、CAB Quantum は引き続き未対応です。

## English

Improved association launches and archive decoding performance. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.21.0 / GyoshukuKit 0.16.0 / Sparkle 2.10.1.

### Improvements

- **Welcome is suppressed when opening through a Finder association**, even when “Show the welcome window at launch” is enabled. An already visible Welcome window is closed. Archive opening itself is unchanged.
- **LZ4 decoding is now parallel** after validating every independent block’s grammar and exact output size. With the fixed corpus, text took 0.8686 / 0.7664 of the baseline time on M4 Max / Mac mini M4, and 50,000 small files took 0.9400 / 0.8979.
- **Deflate64 is faster**, at about 0.92–0.93 of the baseline time on the ZIP and 7z measurements.
- **CAB LZX is substantially faster**, taking 0.4535 / 0.4386 of the baseline time on the real product.cab with 106 files.
- **RAR15 solid decoding also improved**, taking 0.7778 / 0.7340 of the baseline time with a single thread.

The user interface and editing / saving model are unchanged from 0.10.8. See KaitoKit’s [decode performance and stability record](https://github.com/shunnag/KaitoKit/blob/v0.21.0/Documentation/verification/2026-11-03-decode-performance.md) for measurement details.

### Known issues

- After an open archive is renamed or moved in Finder or elsewhere, preview, Quick Look and extraction in its window
  may stop working. This problem predates this version; reopening the window fixes it. It will be fixed in a future version.
- The app's codec dictionary limit is 1 GiB. RAR5 compression version 1 archives that need a larger allocation cannot be extracted
  with the current app settings. KaitoKit supports them when its API limits are raised; relaxing the app's limit remains future work.
- Custom RAR VM programs, continuation of RAR 1.3 / 1.4 volumes from Data, non-ASCII passwords for these old archives, and CAB Quantum remain unsupported.
