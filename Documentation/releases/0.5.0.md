# KaitoFinder 0.5.0

tar.xz と tar.bz2 を開く速さを大きく改善し、7z のヘッダ暗号化の判定と分割アーカイブの保存取り消しの不具合を修正しました。macOS 26 以降、Apple Silicon 専用。

## 改善（速さ）

KaitoKit 0.12.0 / GyoshukuKit 0.7.0 の改善を反映しました。以下の数値は開発時の比較計測の例です。所要時間はアーカイブの内容や環境によって変わります。

- 複数ブロックの tar.xz（`xz -T0` や KaitoFinder 自身が作ったもの）を開くとき、ブロックを並列に展開します。M4 Max で 256 MiB のテキストの tar.xz（11 ブロック）を開く時間が 2.0 秒から 0.4 秒に、KaitoFinder が作った 18 ブロックのものは 1.9 秒から 0.3 秒になりました。1 ブロックの xz はこれまでどおりです。
- 単一ストリームの tar.bz2（bsdtar や bzip2 コマンドが作るもの）を開くとき、ブロック単位で並列に展開します。M4 Max で 256 MiB のテキストの tar.bz2 を開く時間が 5.5 秒から 0.95 秒になりました。
- 並列展開で使うメモリは 512 MiB を上限とし、大きなブロック（`xz -9 -T0` など）ではこれまでどおり順に展開します。

## 修正

- 7z のヘッダ暗号化の判定が I/O エラーなどで失敗したとき、「暗号化なし」と誤って扱わなくなりました。開くときはエラーとして開けず、保存後の再読込では保存前の設定を維持します。
- 分割アーカイブの保存を公開前に取り消したとき、取り消しをそのまま報告し、再ハッシュや保存失敗への読み替えをしなくなりました。証明済みの巻き戻しの後は、取り消された操作からでも再試行できます。
- 未完了の作業台帳の稀なエラー文言が「POSIX <番号>: <説明>」の形になりました。
- 展開を途中で終えた経路で報告する進捗の件数を見直しました。

## 変更と注意

- 圧縮された単一ファイルのうち `.taz` は `.tar.Z` と同じ扱いになり、単一項目として表示するときの名前が `x.taz` から `x.tar` になります。`.tar.bz` の扱いは変わりません。
- 保存中に作る一時ファイルは名前を持たなくなり、保存先のフォルダに `.gyoshuku-` で始まる隠しファイルが現れなくなりました。
- 内部の整理（KaitoKit / GyoshukuKit のソース配置の見直し）を含みますが、対応形式と書き出す書庫の内容は変わりません。
