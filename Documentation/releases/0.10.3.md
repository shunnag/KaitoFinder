# KaitoFinder 0.10.3

0.10.2 で入れた、使っていないアーカイブのファイルを閉じて必要時に開き直す変更を取り消しました。macOS 26 以降、Apple Silicon 専用。

KaitoKit 0.15.0 / GyoshukuKit 0.12.0 / Sparkle 2.10.0 を同梱。

## 修正

- 0.10.1 と同じく、アーカイブを開いている間はファイルを開いたままにする方式へ戻しました。0.10.2 では、「変更の書き込み」を「保存時にまとめて書き込む」にして開いたアーカイブを Finder で名称変更・移動したあと、ほかのアーカイブを十数冊以上開くと、コピーや展開が「No such file or directory」で失敗することがありました。
- **訂正:** 0.10.2 のリリースノートにある「開けるファイル数の上限（通常 256）に達して失敗する」という説明は、KaitoFinder には当てはまりませんでした。KaitoFinder は 0.10.0 から起動時にこの上限を引き上げており、通常は 10,240 です（OS が許す上限がこれより低い場合はその値）。
- 0.10.2 のほかの修正は引き続き含まれています。分割アーカイブの巻の確認中の読み取りエラーを正しく分類する修正（KaitoKit 0.15.0）と、7z の更新で多数のフォルダを再圧縮・暗号化しなおす際に一時ファイルを開きすぎる問題の修正（GyoshukuKit 0.12.0）は維持しています。

## 既知の問題

- 開いているアーカイブを Finder などで名称変更・移動すると、そのウインドウでプレビュー・クイックルック・展開ができなくなることがあります。以前の版からある問題で、ウインドウを開き直すと直ります。今後の版で修正します。

## English

Reverted the 0.10.2 change that closed idle archive files and reopened them when needed. Requires macOS 26 or later and Apple Silicon.

Includes KaitoKit 0.15.0 / GyoshukuKit 0.12.0 / Sparkle 2.10.0.

### Fixed

- As in 0.10.1, files now stay open while their archives are open. In 0.10.2, with "Write changes" set to "Together When Saving", renaming or moving an open archive in Finder and then opening a dozen or more other archives could make copying and extraction fail with "No such file or directory".
- **Correction:** The 0.10.2 release note's description of reaching the open-file limit (usually 256) did not apply to KaitoFinder. Since 0.10.0, KaitoFinder has raised this limit at launch, normally to 10,240 (or the maximum allowed by the OS if lower).
- The other fixes from 0.10.2 remain: correct classification of read errors while checking split-archive volumes (KaitoKit 0.15.0), and the fix for opening too many temporary files when a 7z update re-compresses or re-encrypts many folders (GyoshukuKit 0.12.0).

### Known issue

- After an open archive is renamed or moved in Finder or elsewhere, preview, Quick Look and extraction in its window may stop working. This problem predates this version; reopening the window fixes it. It will be fixed in a future version.
